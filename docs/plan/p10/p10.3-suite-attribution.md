# P10.3 — Suite attribution: tests that spawn the real binary

Branch `p10-suite-attribution` (worktree `.claude/worktrees/p10-suite-attribution`), after P10.1 is on `main`. Read `common.md`, the plan's `#### P10.3`, ADR-149 (yours, P10.1), ADR-083 §1 (a test process that started children is exported with every executable beside the test binary) and ADR-084 §7. ADR number: **151**.

## The owner's ruling

Tag the slow integration tests that spawn the real binary so coverage attribution never reruns them for a change that does not touch what they cover; report the count of such tests in the envelope's reused figure.

## The problem

Cupel's integration tests (`crates/cupel-cli/tests/**`, `crates/cupel-fixtures/tests/matrix.rs`'s trials) spawn the built `cupel` binary over fixture repositories; their per-test coverage includes every line the binary executed (ADR-083 §1), so a change to almost any function marks all of them stale and the incremental run of P10.1 reruns most of the suite anyway. They are also the slowest tests.

## What to build

1. **ADR-151.** How a test is tagged and what the tag means. Prefer a declaration in `cupel.toml` over an annotation in the test source: `[lang.rust] tests = { whole_binary = ["cupel-cli::*", "cupel-fixtures::matrix::*"] }` (names yours; nextest filter syntax for Rust, node-ID globs for Python) — a tagged test *owns* the files its filter names and the fixture repository it runs (ADR-083's owned files) and is attributed, for staleness, to those files and to the public entry points it drives (the `cupel-cli` crate) rather than to every line of every crate the binary executed; its measured coverage still counts in the `CoverageMap` (nothing about `tests.coverage`'s value changes). A change that touches a tagged test's own files, its fixtures, or the crates the tag names reruns it; a change elsewhere keeps it, and the kept count is reported in the envelope's `reused` figure with a separate `reused_tagged` (names yours) so the owner can see the tag's effect. `--depth deep` reruns everything, as in P10.1. `tests --impacted` shows which impacted tests the tag kept and why.
2. **Cupel's own `cupel.toml`** tags its binary-spawning tests; `make dogfood`'s changed gate (which runs at `deep`) is unaffected; `cupel check --changed --depth standard` is what gets faster. Record what the tag keeps and reruns on the P10 change.
3. **Fixture and golden**: extend P10.1's fixture with a tagged test that spawns a binary (a tiny `cargo run` of the fixture's own crate is enough) and a golden showing it kept for a change elsewhere and rerun for a change in its own file.
4. **Measure** before (your P10.1 tip as merged) and after with `make inner-loop`; `**P10.3 — measurement**`.

## Leave alone

As P10.1's brief, plus whatever P10.2 merged in `crates/cupel-mutate/**`: a tagged test that covers a mutant is still a covering test for the engine (the mutation engine's selection is by executed lines, not by attribution; say so in the ADR).
