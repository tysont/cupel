# P10.2 — The mutation engine's per-mutant breakdown

Branch `p10-engine` (worktree `.claude/worktrees/p10-engine`). Read `common.md` first, then the plan's `#### P10.2` heading, ADR-080 (the engine), ADR-082 (Rust schemata), ADR-083 §6 (per-test selection at `standard`), ADR-141, ADR-147 (the mutant time cap), ADR-148 (slots and memory). ADR number: **150**.

## The owner's ruling

Instrument one mutant end to end and report compile / overlay / selection / test-run time. Confirm schemata is engaging on Cupel's own Rust workspace and that per-test selection narrows to the covering tests; fix whatever dominates. Target: under 15 s per mutant after the first build on this repository.

## What is known

On a one-function change in `crates/cupel-checks/src/metrics.rs` at `standard`, the engine takes 285 s for 2 mutants (both `schemata`, both killed) and 412 s for 3 (P4 Notes "P4 — Definition of Done, remeasured"); on 2026-10-16 it was 311 s for 2 mutants: "141 s each in parallel slots, the remaining ~170 s the slots' sync with the tree, their schemata builds, and validation", and the 16 covering tests "take over two minutes because Cupel's matrix tests run every check over every fixture" (P3 Notes "P3.6 — measurement on a quiet machine"). Nothing since has measured the phases apart.

## What to build

1. **The breakdown.** Per mutant (or per schemata file run), the engine records the time of each phase: the overlay sync (`overlay.rs`), the schemata rewrite and the instrumented build (compile), the covering-test selection (how many of the suite's tests, which), and the test run (`execute.rs`), into `MutationOutcome` (or a sibling the outcomes fact carries) and the store's `durations` table under `engine.mutation.<phase>` so `cupel check --format json` and `cupel explain` show them and `scripts/inner_loop.sh`'s durations query lists them. `cupel describe fact mutation-outcomes` and the schema follow.
2. **Confirm or fix schemata.** Prove, with the breakdown on Cupel's own workspace, that mutants of `cupel-checks` run as schemata (one build per file, mutants switched by an environment variable or equivalent, ADR-082) and not as file copies with a rebuild each; and that selection narrows to the covering tests (names and count in the breakdown). If either does not hold on this workspace, that is the first fix.
3. **Fix what dominates.** Likely candidates, to be confirmed by the numbers, not assumed: the overlay copy of a 600-file workspace with its `target/` (sync only what changed; share the instrumented `target/cupel-llvm-cov` read-only; hard-link); a full `cargo build` of the schemata when only one crate changed (build only the covering tests' binaries: `cargo nextest run --no-run -p <crates>` with the exact test binaries, `--lib`/`--test <name>`); covering tests that are slow matrix trials (run the trial, not the harness: nextest's per-test filter already does this — confirm the filter is per trial, not per binary); the slots' serialization behind the heavy lock or the memory budget (ADR-148: four slots, half of physical memory). One change at a time, measured.
4. **The target.** Under 15 s per mutant after the first build, on this repository, on the P10 change; record what each mutant costs before and after, phase by phase, in `**P10.2 — measurement**`, and the inner-loop table (`make inner-loop`) before and after.
5. **ADR-150** before the code that changes behaviour: what the breakdown records, what changed in the engine and why, with the measurements as the evidence. Tests for every behaviour change (the overlay, the build set, selection) through the engine's existing test seams in `crates/cupel-mutate/tests` and the `gen`/`tests.mutation` fixtures' goldens (additive: new breakdown fields).

## Leave alone

`crates/cupel-adapt/src/{suite,per_test}/**` and `crates/cupel-core/src/{per_test.rs, per_test_impact.rs, joint.rs}` (P10.1's); `.github/workflows/release.yml`, `crates/cupel-cli/tests/install*.rs`, `crates/cupel-checks/src/tests_coverage.rs` (P10.4's). The engine's reuse keys (ADR-080 §10), the score (ADR-141), the time cap (ADR-147), and the memory budget (ADR-148) are settled; changing them needs an owner ruling.
