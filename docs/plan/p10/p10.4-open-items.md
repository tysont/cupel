## 1. The Linux release cache is not restored on a tag run

`.github/workflows/release.yml` restores `Swatinem/rust-cache` with `key: ${{ matrix.target }}`; the dry run (`workflow_dispatch` on `main`, run 40596917228) was meant to seed it. On the tag run (40606071936) macOS and Windows restored their caches and the two Linux targets (`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, both through `cargo-zigbuild`) logged "No cache found". Find out why from the two runs' logs (`gh run view <id> --log` for the `Post Run Swatinem/rust-cache` steps of the Linux jobs: was a cache saved at all, with which key, and what key the tag run looked for; rust-cache's key includes the job, the `key` input, the lockfile hashes, the rustc version, and the environment; `cargo install cargo-zigbuild` after the cache step changes `~/.cargo/bin`, which rust-cache does not cache, but may matter to its key or its save). Fix the workflow so a dry run seeds what a tag run restores, for every target; prove it with a `workflow_dispatch` run followed by a second `workflow_dispatch` run that restores (both are dry runs: archives only, nothing published; ADR-143). Record both run IDs and the restore lines in `**P10.4 — release cache**`.

## 2. `tests.coverage` passes a changed file no test imports

coverage.py's lcov has no row for a file never loaded, so `tests.coverage` reports `lines 0` and passes for a changed Python file no test imports, while `tests.mutation` sees the same file's mutants uncovered (P9 Notes "P9 — v0.2.0"). Two halves, both needed: (a) `cupel init`'s pytest coverage command passes a source (`--cov=<package or root>` per detected root, as pytest-cov documents), so coverage.py reports every file under the source, loaded or not, as 0 %; keep the joint's "default command" comparison (ADR-084 §3) accepting the command `init` now writes; (b) `tests.coverage` itself: a file in the scope with symbols but no row in the coverage map is *uncovered*, not *unmeasured*, when the map covers other files of the same language and root — report its lines as 0 hits with a finding kind that says the file was never loaded (`coverage.unloaded-file`, names yours), and exclude files the language cannot load (a `__main__`-only script is still loadable; a fixture under `tests/` is excluded by scope). ADR-152 records the rule and which languages' maps it applies to (lcov from llvm-cov lists every instrumented file, so Rust is unaffected; Go's profile lists only packages that ran; JaCoCo lists every class). Fixture: the P9 `shop` repository's shape — a Python package with one module no test imports; golden: the finding and `lines 0 / N`.

## 3. The two network-dependent baseline tests

`fix_with_install_installs_the_runner_into_a_scratch_venv_and_passes` (`crates/cupel-cli/tests/install.rs`) and `each_wrapper_refuses_a_bad_checksum_downloads_once_and_forwards_the_exit_code` (`crates/cupel-cli/tests/installers.rs`) download from the network and fail a tree dogfood when the machine is offline or on battery. ADR-153 decides, per test: make it hermetic (a local index or a file:// release served from the test's temp dir — the wrapper tests already have a bad-checksum path; serve the archive from a local HTTP server or `file://` URL the wrapper accepts) or move it to a network-gated target (`make test-network`, run by CI's `installers` job and never by `make test` or the dogfood baseline, with the test marked by a feature or an environment variable it checks and `skip`s with a reason). Hermetic is preferred where the test's subject is the wrapper's logic; gated where the subject is the real download. Both tests still run somewhere in CI on every push.
