# P9.5 — `#REQ-n` markers as a secondary traceability source

Branch `p9-req-markers`. Read `common.md` first, then the plan's `#### P9.5` heading, ADR-114, and design §5's `meta.traceability` row and open question 5 ("lean toward both"). ADR number: **134** (amends ADR-114; change ADR-114's status line to say so).

## Scope (track (a) item 5)

Configured requirement IDs (`[traceability]` in `cupel.toml` or `--spec FILE`) stay the primary source. The secondary source is a `REQ-<n>` marker (`#REQ-12`, `REQ-12`, `req_12` in a test name or in the test's doc comment or docstring, per language) that names a requirement the configuration does not list. Rules to decide and record in ADR-134: which spellings count, per language; whether a marker in a test body counts (expected: names and doc comments only); what `meta.traceability` reports for a marker with no configured requirement (expected: the test is traced to that requirement and the requirement is listed as `source: marker`); and that a configured requirement traced only by markers still satisfies the check. The envelope's traceability evidence gains the requirement's `source` (`config | spec | marker`), additively. Fixture cases for every language `meta.traceability` supports, each with a marked test, through the matrix test. `describe` and the README's check table say what the check reads.
