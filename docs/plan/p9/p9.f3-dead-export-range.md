# P9.F3 — Follow-up fix: `dead.export` under a range reads the whole module graph

Branch `p9-dead-export-range`. Read `common.md` first, then the plan's `#### P9 Notes` bullet **P9 — follow-up list**, item (21), the **P9.6 — open items** bullet (its item 6), ADR-058, ADR-059, ADR-135 (how `References` covers every file of the language whatever the scope), ADR-142 (a range's scope is the symbols its changed lines touch), and ADR-143 (which names item 21 as the one bug P9 does not defer). ADR number: **144**. The item you close is struck from the follow-up list with a pointer to the ADR.

## (21) A false `dead.export` under a range

`static.dead-code`'s module pass (`Reachability::of` in `crates/cupel-checks/src/static_dead_code.rs`) decides whether a `pub` item's module is imported from the `ModuleGraph` fact it is handed. Under `--changed` or `--base` that fact covers the scope's files, so an export of a touched file that only an unchanged file imports has no importer in the graph and is reported `dead.export` (`info`, low confidence): a finding invented, not missed. `References` (ADR-135) already covers every file of the language whatever the scope, for the same reason: a caller outside the scope still counts.

Decide and record in ADR-144 how the module pass sees the importers outside the scope. The principled options are: (a) the `ModuleGraph` producer covers every file of the language, as `References` does (then every consumer of the fact sees the whole graph: say which consumers exist, `static.deps` among them, and what changes for each, since `dep.cycle` under a range must keep reporting cycles among the changed files only); (b) the dead-code check asks for the whole-language graph through the same mechanism `References` uses, leaving the scoped fact to the other consumers. Measure the blast radius before building (which goldens move; a `--changed` golden losing a false `dead.export` is the fix, and is justified line by line in the notes).

Prove it with a fixture case first: a range fixture in `crates/cupel-fixtures` where a touched file's `pub` item is imported only by an unchanged file, failing today with `dead.export` and passing after the fix, in at least one native language (Rust, Python, or TypeScript) and one adapter language if the fixtures make that cheap. Then confirm on Cupel itself: `make dogfood` on your branch (the changed gate) reports no `dead.export` on a `pub` item another crate imports; add a temporary `pub fn` used only from an unchanged file, see it is not reported, and remove it.

## Leave alone

Everything outside `static_dead_code.rs`, the module-graph producer and its registration (if option (a)), the fixture, and the goldens the fix moves. Nothing in the gate, the renderers, the daemon, `cupel-mutate`, or the clone and complexity checks.
