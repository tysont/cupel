# P9.F6 — Follow-up fix: a hard cap on a mutant's run, and tests no runner can narrow

Branch `p9-mutant-timeout`. Read `common.md` first, then ADR-083 (per-test selection: nextest filtersets), ADR-077 (`PerTestMap`), ADR-141 (the score and uncovered mutants), the README's mutation section (§ Timeouts: a mutant gets `timeout_factor` times the unmutated run, at least two seconds), `crates/cupel-mutate/src/{settings,execute,engine}.rs`, `crates/cupel-adapt/src/per_test/` and `crates/cupel-adapt/src/suite/`, and the plan's `#### P9.9` heading. ADR number: **147**.

## The defect

Group 1's deep run on serde_json held the machine for five hours: a mutant that turns a parser's loop into one that never ends makes `cargo test`'s integration binary (one process holding every test of `tests/test.rs`) run until `timeout_factor × baseline`, and that binary's baseline is long, so each such mutant cost about nine minutes. Per-test selection (ADR-083) cannot narrow those tests: nextest runs each test in its own process, but a `trybuild` compile test, an integration binary whose tests share state, or a runner that cannot run one test by name (`go test -run` can; Surefire can by class; Cupel's Clojure runner cannot) is run whole. The owner's ruling:

1. **`max_mutant_timeout`** (default `120s`, a duration) under `[checks."tests.mutation"]` in `cupel.toml`: a hard cap on a mutant's run on top of `timeout_factor`. A mutant whose run reaches the cap is a `timeout` outcome as today. If the config has no `[checks.<id>]` table yet, add the mechanism for this check (the config schema, `describe schema config`, the README), keeping `[lang.<id>] mutation = {...}` where it is; record the placement in the ADR.
2. **Tests no runner can narrow**: when per-test selection cannot run a test on its own (document per runner which tests can be narrowed and which cannot: cargo-nextest, cargo-test, go test, pytest, unittest, jest, vitest, Surefire, Cupel's Clojure runner), a test whose baseline run is longer than 60 s is excluded from every mutant's run, and the check emits one `info` finding `mutant.slow-test-excluded` per excluded test, naming the test and its baseline duration. `describe` lists the finding kind; the manifest declares it; the score counts those mutants as today over the tests that did run.
3. **Fixture case first**: a fixture in `crates/cupel-fixtures` with a test that loops under one mutant (a mutated loop condition) so the cap cuts it, and one with a slow unnarrowable test (an integration binary whose baseline the fixture makes long enough with a sleep, or a trybuild-shaped test) that is excluded with the finding. Goldens additive.
4. `make check`, `make parity`, `make dogfood` on the branch; the plan heading `#### P9.F6` after P9.F5 with the notes bullets.

The score formula (ADR-141), the operators, the slots (ADR-141), the per-test map producers' coverage logic (only their "can this runner run one test" knowledge is added), the gate.
