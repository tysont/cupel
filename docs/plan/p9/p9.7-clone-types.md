# P9.7 — Clone type 1 vs type 2 in evidence

Branch `p9-clone-types`. Read `common.md` first, then the plan's `#### P9.7` heading, ADR-050 (amended by this step: set its status line), and design §5's `static.clones` row. ADR number: **136**.

## Scope (track (a) item 7)

`static.clones` matches on normalized subtrees, so a type-1 (identical) and a type-2 (renamed identifiers or literals) clone look the same. Add a raw-token digest beside the `NormTree` fingerprint (the token sequence with identifiers and literals kept), so a pair or cluster carries `clone_type`: 1 when the raw digests match, 2 when only the normalized ones do, 3 for the near-miss similarity matches, with the evidence saying what differs for type 2 (the identifiers and literals that differ, as pairs) and for type 3 (the inserted or removed statements). Additive: the finding's evidence gains fields, the goldens of every clone fixture gain them, no existing value changes. `describe` and the README's check table name the three types. Fixture cases: one of each type in at least two languages through the matrix test.
