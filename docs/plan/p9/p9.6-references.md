# P9.6 — `References` fact and real dead-symbol detection

Branch `p9-references`. Read `common.md` first, then the plan's `#### P9.6` heading, ADR-058 (which this step supersedes: set its status line), and design §7's fact table (`ModuleGraph`, `Roots`, `Symbols`). ADR number: **135**.

## Scope (track (a) item 6)

A `References` fact for every language Cupel parses natively and through adapters: for each symbol in `Symbols`, the locations that name it (calls, reads, type uses, re-exports), resolved through the `ModuleGraph` imports where the language allows (same-file and imported names resolve; dynamic access is recorded as unresolved, never guessed). `static.dead-code` decides reachability per symbol: a symbol with no reference outside its own definition and no root by convention (`Roots`: entry points, exports, tests, framework hooks) is `dead.symbol`; file- and module-level reachability (ADR-058) stays as the first pass. Confidence is lowered, not raised, where references are unresolved (a language with dynamic dispatch reports `dead.symbol` at low confidence or not at all; say which in ADR-135 per language). The fact is registered in the fact registry with its producers per language, appears in `describe matrix`, and has fixture cases per language through the matrix test: a dead function, a function reached only through an import, a function reached only dynamically, and an exported one. This is a check whose false positives cost trust: every rule that suppresses a finding is written down.
