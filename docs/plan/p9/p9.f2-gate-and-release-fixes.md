# P9.F2 — Follow-up fixes: the changed gate's scope, the release workflow, the agent guide, the version bump, and the deferrals

Branch `p9-gate-fixes`. Read `common.md` first, then the plan's `#### P9 Notes` bullet **P9 — follow-up list**, items (9)–(15) and (18), and the ADRs each names. ADR numbers: **142** (item 18) and **143** (the deferrals). Items you close are struck from the follow-up list with a pointer to the ADR or the commit.

## (18) The changed gate rules on what the range touched

With `--changed`, `static.clones` `none` reports a pair that existed at the base when a member's file is in the changed scope, `tests.coverage` `none` reports uncovered functions the range never touched in files it touched, and the same for every other `none` rule: every P9 branch's changed-gate dogfood failed on findings it did not write. Read design §6.4 (scope resolution), ADR-056 (the changed files and lines of a range), and how `ChangedLines` reaches the checks (the mutation engine already mutates only the changed lines). Decide and record in ADR-142 how a range scope narrows findings: the principled rule is that a finding belongs to the range when its location intersects the range's changed lines (for a clone pair or cluster, when at least one member's span does; for a per-symbol finding, when the symbol's span does), and a finding outside the range is still computed (the facts are per file) but reported with a flag or left out, whichever the design's "scope" means (say which, and why). Measure the blast radius before building: which checks and goldens change (the `--changed` fixtures). Then prove it on Cupel itself: `make dogfood` on your branch must no longer report the clone pairs P9.4–P9.7 listed as pre-existing, while a new clone pair you add in a test (and remove) is reported.

## (10) A build cache in the release workflow

`release.yml` builds five targets from scratch. Add `Swatinem/rust-cache` pinned by commit sha as the other actions are (`release.rs` checks the pins), keyed per target, and record the before/after times from the next tag run in the notes when known (the integrator tags v0.2.0; leave a line for the measurement).

## (12) The agent guide names every flag

The README's generated "For agents" section is written by `agent.rs` by hand, so a new flag it should mention is not caught. Add a test that every long flag of `check`, `survey`, `explain`, and `serve` (from clap's command definition, not from a list in the test) is named in the guide, with an explicit allow-list of flags the guide need not mention and a reason for each; make the guide name the ones the test finds missing.

## (13) One version, three files

A version bump edits the workspace `Cargo.toml`, `dist/npm/package.json`, and `dist/pipx/cupel.py` (find the exact files). Add a test that the three agree and a `make version V=X.Y.Z` target (through `scripts/release.sh version --set` or a new subcommand of it, ShellCheck-clean, tested) that rewrites all three; the README's Makefile table gains the row.

## ADR-143: the deferrals

For each item that stays open after this step, one ADR with a section per item saying what it is, why it is deferred, and what would reopen it: (9) musl allocator speed under rayon unmeasured; (11) the aarch64 Linux and x86_64 macOS binaries are not executed in CI (no such runners in the free tier; the release's install verification covers them by hand); (14) the wrappers' Windows paths untested (depends on P9.8's Windows CI job; say what it would take); (15) the schema site serves `main`'s tip, not a release (versioned paths under `schema/v1/` are the contract; a breaking schema change is `v2`); and any P9.4–P9.7 open item the plan lists that is not a bug (say which ones are deferred and which are bugs that stay on the follow-up list with a reason). The P9 Definition of Done requires every remaining follow-up item to have this.
