# Checks

Every check below exists. Each is supported in all seven languages except `gen.property`, which Go, Java, and Clojure lack (Cupel runs no property framework for them); `gen.metamorphic`, which has a Python harness only; `conc.race`, which has race detectors for Go and Rust only; `gen.fuzz`, which has no TypeScript, Java, or Clojure fuzzer; `perf.bench`, which has no Java or Clojure bench tool; `conc.dst`, which has a simulator for Rust only (madsim); `conc.model-check`, which has a model checker for Rust only; `spec.contracts`, which reads Rust's `contracts` crate and Python's icontract only; and `gen.differential`, `static.analyze`, and `perf.footprint`, which have no Java or Clojure harness, analyzer, or lockfile reader yet; the [support matrix](languages.md#languages) says `unsupported`. All run at `--depth quick` except `gen.property`, `tests.coverage`, `tests.flaky`, `tests.mutation`, `conc.race`, and `spec.contracts`, which run the project's test suite, `meta.traceability`, and `static.analyze`, which runs its type checkers and linters, so they run from `--depth standard`, the default; and `gen.differential`, `gen.metamorphic`, `gen.fuzz`, and `perf.bench`, which run from `--depth deep` (or by name with `--only`), the first two once a language lists the functions it compares or declares relations (see [Differential testing](generative.md#differential-testing) and [Metamorphic relations](generative.md#metamorphic-relations)); `conc.linearizability` also runs from `--depth deep`, once a language names the command that records its histories; and `conc.dst`, `spec.trace`, `conc.model-check`, and `spec.prove` run from `--depth exhaustive` (or by name with `--only`), `spec.trace` once a spec oracle is defined (see [Trace validation](specifications.md#trace-validation)). The table is generated from `cupel describe` (see [Development](development.md)). Tier is the strength of the evidence, from 0 (structural) upward. Gate metrics are the keys a gate rule can name as `<check>.<metric>`; ranked metrics are what `survey` ranks.

Tier `—`: the `perf.*` checks measure speed and size, not correctness, and tiers grade correctness evidence (`describe` reports them at tier 0). From tier 4, the Languages column names each language's tool, or `any` when one tool serves every language.

What each check looks for:

- **`static.complexity`** measures every function's cyclomatic and cognitive complexity, nesting depth, parameter count, and length against configurable limits. A `match` or `switch` counts as one decision however many arms it has.
- **`static.crap`** scores each function by complexity weighted by missing test coverage, from the language's coverage report (see [Coverage](coverage-and-mutation.md#coverage)); without one it passes with a null score and no findings rather than guess.
- **`static.clones`** finds functions whose normalized syntax trees are mostly the same, so renamed variables and reformatting do not hide a copy. Two members are a `clone.pair`; three or more are a `clone.cluster`. Each says its `clone_type`: 1 for the same tokens (only layout, comments, or the function's name differ), 2 for the same tree with identifiers or literals renamed (listed in `renamed`, one text per member), 3 for statements inserted, removed, or changed (listed in `edits`, with where each is). A group whose members all lie in test files is reported at `info` with `shape` `test-code` and is not counted in `pairs`, `clusters`, or `max_jaccard`, so it does not move the clone gate ([ADR-184](../adr/CUPEL_DECISION_184.md)).
- **`static.deps`** builds the module graph from resolved imports. It reports import cycles, modules that are both unstable and abstract, and imports that break the layering you configure. A module's abstractness is the share of its exported members that are abstract: interfaces, abstract classes, and type aliases are abstract; exported functions, concrete classes, and values are concrete ([ADR-178](../adr/CUPEL_DECISION_178.md)). A cycle follows only the imports used at run time: a TypeScript import of types alone (`import type`, or every name marked `type`) is erased by the compiler, so it couples modules but closes no cycle ([ADR-165](../adr/CUPEL_DECISION_165.md)); so does a Python import under `if TYPE_CHECKING:` or `if typing.TYPE_CHECKING:`, which runs only for a type checker ([ADR-211](../adr/CUPEL_DECISION_211.md)).
- **`static.dead-code`** reports symbols and exports in modules that no import reaches and no entry point, test, framework hook, or test file (one the runner finds by its path, such as a Rust bench) keeps alive. A file the project's own manifests say it runs also keeps its module alive: for JavaScript and TypeScript, `package.json`'s `main`, `bin`, and the files its scripts run with `node`, `tsx`, `ts-node`, or `bun`, a `wrangler*.toml`'s `main`, and the sources a `Dockerfile` copies into its image ([ADR-163](../adr/CUPEL_DECISION_163.md)). JavaScript and TypeScript are judged together, so a module of one that the other imports or runs is reached. Reachability is decided per module, not per call, so an export of a module nothing imports is reported as `info` with low confidence: it may be public API.
- **`tests.quality`** reads every test: tests with no assertions or only weak ones (truthiness, presence, inequality, a range; `toContain`, `toMatch`, and `toMatchObject` pin what they name and are not weak, [ADR-184](../adr/CUPEL_DECISION_184.md), nor are Chai's `include`, `contain`, `match`, `deep.include`, `assert.include`, and `assert.match`, [ADR-200](../adr/CUPEL_DECISION_200.md)), heavy mocking, loops and branches inside tests, and duplicated setup. A loop whose body holds an assertion runs a table of cases and is not logic; a branch is. Duplicated setup is at least `setup_tests_min` (3) tests of one file repeating at least `setup_statements_min` (5) leading statements. A call to an asserting function of the same file counts as that function's assertion. A Go test that hands its `t` to a function or method of its package (any file of the directory in scope, test file or not) asserts as that helper does, and not at all when the helper only sets up (`t.Helper()`, `t.Cleanup`, `t.TempDir()`) ([ADR-207](../adr/CUPEL_DECISION_207.md)). A Rust `r.unwrap_err()` or `r.expect_err(…)` panics unless `r` is an error, so it is the weak throws check `assert!(r.is_err())` is; `unwrap` and `expect` are setup and assert nothing. A Rust test that calls a helper through a module path (`common::check(…)`, `crate::common::check::<T>(…)`) asserts as that helper does when the file the path names (`common.rs` or `common/mod.rs` beside the test file or in the nearest directory above it in scope) defines it asserting, and not at all otherwise ([ADR-214](../adr/CUPEL_DECISION_214.md)). Heavy mocking counts the doubles a test makes itself: a module-level mock (`vi.mock`, a class-level `@Mock`) is the file's, not each test's ([ADR-164](../adr/CUPEL_DECISION_164.md)).
- **`static.api-surface`** compares the public API at the range's base with the API now, path by path. A public item that is gone (deleted, renamed, or made private) or lost a signature is `api.breaking` (`warn`); one that is new, gained a signature (an overload), or gained trailing parameters a caller may leave out (optional, defaulted, or variadic) is `api.widened` (`info`). An item moved to another module is unchanged at its old path when the old module re-exports it (`export … from`, `pub use`); it is compared with what the re-export names ([ADR-174](../adr/CUPEL_DECISION_174.md)). For JavaScript and TypeScript, a package's API is what the nearest `package.json` exposes: the files its `exports` map names (every subpath and condition; a `*` target exposes every file it matches), or without one its `main` and `types`, and what those re-export; built output such as `./dist/index.js` stands for the same path under `src`. Any other exported item is internal, so moving, renaming, or removing it is neither breaking nor widening, and a package whose manifest names no entries has no API ([ADR-176](../adr/CUPEL_DECISION_176.md), [ADR-192](../adr/CUPEL_DECISION_192.md)). For Clojure, a project's API is what its published source paths hold: the top-level `:paths` of the nearest `deps.edn` (`src` when it names none), or the top-level `:source-paths` of the nearest Leiningen `project.clj` (`src` likewise). A var elsewhere, such as a dev script on `bb.edn`'s `:paths`, a build script, or a file on an alias's `:extra-paths`, is internal; a file under no `deps.edn` or `project.clj` keeps every public var as API ([ADR-215](../adr/CUPEL_DECISION_215.md)). In every language, an item defined in a test file (by the language's test conventions, such as `test/**` for Clojure or `*_test.go` for Go) is no package's API: changing, removing, or adding one is neither breaking nor widening. Metadata on a Clojure parameter vector or parameter, such as a type hint (`^String [s]`, `[^long n]`), is no part of a signature. It needs `--changed` or `--base`, and the gate rule `"static.api-surface" = "no-breaking"` holds a branch to no unsuppressed break.
- **`static.analyze`** runs each language's type checker at its strictest and its linters, and reports every result in a file in scope as `analyze.<tool>.<rule>` (`analyze.mypy.arg-type`, `analyze.clippy.needless_return`): errors `fail`, warnings `warn`, notes `info`. See [Analyzers](analysis.md#analyzers).
- **`perf.footprint`** reads the dependencies the lockfiles list, without network access, and reports those with a known vulnerability (`dep.vuln`) or a copyleft license (`dep.license`); under a range it reports only dependencies the range added or changed, and `footprint.grew` when there are more than at the base. See [Dependencies and footprint](analysis.md#dependencies-and-footprint).
- **`tests.assertion-density`** measures assertions per test and per tested public function (one whose file has tests). It reports long tests that assert little for their length (`density.sparse-test`) and test files whose assertions per test fall far below the repository's (`density.sparse-file`); a test that asserts nothing is `tests.quality`'s.
- **`tests.weakening`** compares the tests at the range's base with the tests now. It reports removed or loosened assertions, skipped or deleted tests, and rewritten snapshots. It needs `--changed` or `--base`.
- **`tests.flaky`** reruns the test suite (over a range, the tests it impacts) several times in different orders and with different seeds, and reports tests whose outcome changes: `test.flaky` when two reruns in the same order disagree, `test.order-dependent` when the outcome follows the order. See [Flakiness](languages.md#flakiness).
- **`gen.differential`** calls the functions you name on generated inputs, in the working tree and against an oracle (the same code at an earlier commit, or a command that computes the reference answer), and reports the smallest input on which the two answer differently, with both answers. See [Differential testing](generative.md#differential-testing).
- **`gen.property`** runs the project's existing property tests (proptest and quickcheck, Hypothesis, fast-check) with the run's seed and many more generated cases than the suite usually gives them. A property that fails is `property.falsified`, with the framework's shrunk counterexample; a public function that takes arguments, in a file whose tests hold no property test, is `property.missing` (`info`). A property that sets its own case count runs at it and is `property.cases-pinned` (`info`). See [Property tests](generative.md#property-tests).
- **`tests.mutation`** changes the code in small ways (`<` to `<=`, `+` to `-`, `&&` to `||`, `true` to `false`, `0` to `1`) and runs the tests that cover each change. A mutant every test passes against survived: the tests do not notice that line changing; a site no test runs is uncovered, not run, and missed. The score is killed / (killed + survived + uncovered). See [Mutation testing](coverage-and-mutation.md#mutation-testing).

- **`gen.metamorphic`** evaluates the metamorphic relations you declare (sorting a list and sorting its reverse give the same result; `add(a, b) == add(b, a)`) on generated inputs, and reports each relation that does not hold, with the smallest failing input it could find and both outputs. See [Metamorphic relations](generative.md#metamorphic-relations).
- **`gen.fuzz`** runs every fuzz target the project has (cargo-fuzz targets, Go `FuzzXxx` functions, Jazzer.js and atheris modules) with the run's seed and an execution budget, and reports each input that crashes a target (`fuzz.crash`) or runs past the per-input limit (`fuzz.timeout`), with the saved input and the command that reruns it; a project root with no fuzz target is `fuzz.target-missing` (`info`). See [Fuzzing](generative.md#fuzzing).
- **`conc.race`** runs the tests under a race detector (Go's `-race`; Miri or ThreadSanitizer for Rust) and reports each data race (`race.detected`) and each operation with undefined behavior (`ub.detected`), with the stacks of the accesses inside the repository. See [Race detectors](concurrency.md#race-detectors).
- **`conc.linearizability`** runs the command you name to record histories of concurrent operations (a test or harness writing JSON lines), checks each against the model it declares (a register, a key-value store) with Porcupine, and reports each history, or key, that no order consistent with real time explains (`consistency.violation`), with the operations that cannot come next. See [Linearizability](concurrency.md#linearizability).
- **`conc.dst`** runs the project's deterministic simulation harnesses (madsim's `#[madsim::test]`) over a range of seeds from the run's seed, and reports each harness's first failing seed (`dst.failure`) with what it printed, replayed alone, and the command that replays it. See [Deterministic simulation](concurrency.md#deterministic-simulation).
- **`perf.bench`** runs the project's benchmarks (Go's, criterion, pytest-benchmark, or commands timed by hyperfine) at the range's base commit and in the working tree, and compares each benchmark's samples with a Mann-Whitney U test: a significant slowdown of at least 5% is `perf.regression` (`warn`), a speedup `perf.improvement` (`info`). Without a range there is nothing to compare, and it says so. See [Benchmarks](analysis.md#benchmarks).
- **`spec.trace`** runs the tests with `CUPEL_TRACE_DIR` set, so the implementation logs each step it takes (its state, and the spec action it took) as JSON lines, and validates every recorded trace against the run's TLA+ spec oracle with TLC. A trace with a step the spec does not allow is `trace.diverged`, at the step, with the state logged there and the last state the spec allows. See [Trace validation](specifications.md#trace-validation).
- **`conc.model-check`** model-checks the project's proof harnesses (Kani's `#[kani::proof]` functions for Rust) over every input within their bounds, and reports each property an input breaks (an assertion, an overflow, an out-of-bounds access) as `model.counterexample`, with the values that break it and a test that replays them. See [Model checking](specifications.md#model-checking).
- **`spec.prove`** verifies the project's Dafny proofs, and reports each proof obligation the verifier could not prove (`proof.failed`) and each the proofs assume instead of proving or leave undecided in the verifier's budget (`proof.obligation-open`, `warn`). See [Proofs](specifications.md#proofs).
- **`spec.contracts`** runs the tests again with every contract the project's contract library checks turned on, the debug-only and slow ones too, and its property tests at the case budget, and reports each precondition, postcondition, and invariant a test violated (`contract.violated`), at the contract. See [Contracts](specifications.md#contracts).
- **`meta.traceability`** maps each requirement ID you list to the tests the range added whose names or doc comments carry it (`test_req_12_parses`, `parses week dates #REQ-12`, `/// Parses week dates (REQ-12).`), and reports each requirement no such test names (`spec.untested-requirement`); a `REQ-<n>` marker on an added test that names no listed requirement is listed as one (`spec.unlisted-requirement`, `info`). It needs `--changed` or `--base`. See [Requirements and test provenance](specifications.md#requirements-and-test-provenance).
- **`meta.oracle-independence`** labels each changed function the tests exercise by whether a test that existed before the change runs it, and reports one only the change's own tests run (`evidence.self-authored-only`, `warn`): the only evidence it works was written with it. It needs `--changed` or `--base` and a per-test coverage map. See [Requirements and test provenance](specifications.md#requirements-and-test-provenance).

`cupel describe <check>` and `cupel describe finding <kind>` give the full contract, including each finding kind's evidence schema.
