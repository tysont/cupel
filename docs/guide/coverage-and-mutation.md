# Coverage and mutation testing

## Coverage

`tests.coverage` and `static.crap` read a `coverage-map` fact: line hits, and branch hits where the tool measures them. Cupel runs the coverage command the repository configures — `cupel init --write` writes one per language — and reads the report it leaves, in any of LCOV, Cobertura XML, Istanbul JSON, Go coverprofile, or JaCoCo XML:

```toml
[lang.rust]
coverage = "cargo llvm-cov --lcov --output-path {out}"    # {out}: a report path Cupel chooses

[lang.typescript]
coverage = "npx vitest run --coverage --coverage.reporter=lcov"   # no {out}: coverage/lcov.info
```

| Language | Coverage producers, in default order | Branches |
|---|---|---|
| Rust | `cargo llvm-cov` | no (stable llvm-cov reports none) |
| Go | `go test -coverprofile` | no (coverprofile has none) |
| Python | `pytest-cov` (with pytest, where a manifest declares it), `coverage.py` (with unittest, and with pytest otherwise: `coverage run -m pytest`, [ADR-228](../adr/CUPEL_DECISION_228.md)) | with `--cov-branch` |
| JavaScript, TypeScript | `vitest --coverage`, `jest --coverage`, `node --test --experimental-test-coverage` (for a `node --test` root without `c8` in `devDependencies`), `c8` (with Mocha, or a `node --test` root that lists it) | yes |
| Java | JaCoCo through Maven (its goals by coordinate around `mvn test`; for a build that runs JaCoCo's `prepare-agent` itself, by its `pom.xml` and the parents on disk or in the local repository, `mvn test jacoco:report` with the project's own plugin, since a second agent kills the forked JVM, [ADR-209](../adr/CUPEL_DECISION_209.md)), JaCoCo through Gradle (`gradle test jacocoTestReport`, with the `jacoco` plugin applied and XML reports on) | yes |
| Clojure | Cloverage (`-Sdeps` adds it for the run, with an alias clearing the `:test` alias's `:main-opts`, `--lcov`) | no |

Without a `coverage` command a language's `tests.coverage` is skipped as `unconfigured` and `static.crap` reports no CRAP; with one but without the tool, it is `unavailable` and `cupel doctor` names the tool. A report is reused instead of rerunning the suite while it is fresh: Cupel records the hash of every file under the project root when it makes one (and trusts files not modified since), and a report the tool left at its default location is used when it is newer than every source. A command that exits non-zero gives no coverage and a `coverage.run-failed` finding, since a red suite has no meaningful coverage.

`tests.coverage` reports `coverage.uncovered-symbol` for each function no test ran (a warning, which fails the check), `coverage.uncovered-branch` for a function that ran with a branch no test took, and `coverage.unloaded-file` for each function of a file no test loaded, where the tool lists only the files the suite loaded (coverage.py without a source, [ADR-152](../adr/CUPEL_DECISION_152.md)); `cupel init` passes the source (`--cov=src` or `--cov=.`), so coverage.py lists every file and such a function is an ordinary uncovered symbol. It writes pytest-cov's command only for a root whose `pyproject.toml`, `setup.cfg`, or `requirements*.txt` declares `pytest-cov`; any other pytest root gets `python -m coverage run -m pytest && python -m coverage lcov -o {out}`, which runs with what it declares ([ADR-228](../adr/CUPEL_DECISION_228.md)). A project whose coverage configuration chooses its files (`source`, `source_pkgs`, or `include` in `.coveragerc`, `setup.cfg` or `tox.ini` `[coverage:run]`, or `pyproject.toml` `[tool.coverage.run]`) gets a bare `--cov` instead, since a source would make coverage.py ignore its `include` (a warning that `filterwarnings = ["error"]` makes fatal); its configuration decides what is listed, and a file it leaves out is not reported unloaded ([ADR-208](../adr/CUPEL_DECISION_208.md)). Rust's coverage runs doctests too where `rustup` has the `nightly` toolchain with its llvm-tools component (`cargo +nightly llvm-cov --doctests …` in place of the configured `cargo llvm-cov …`; asked of `rustup` without the network); elsewhere a function no test ran whose own doc comment holds an example rustdoc runs (a fenced block that is not `ignore`, `no_run`, `compile_fail`, or another language) and that names it is `coverage.doctest-only`, a note, since that example alone may cover it, instead of `coverage.uncovered-symbol` ([ADR-231](../adr/CUPEL_DECISION_231.md)). Where the tool measured no branches (Go, Rust), there are no branch findings and the result says `notes: ["branches: unavailable (go)"]`. Its gate keys are `tests.coverage.line` and `tests.coverage.branch` (covered shares), `lines`, `branches`, and `uncovered`. `static.crap` computes `CC² × (1 − coverage)³ + CC` from the same map.

Where a language has several project roots (configured `[roots]` or detected), each root's coverage report holds its own tests only, so code another root's tests exercise reads as uncovered. A per-test map adds them: Python's pytest-cov map measures each root's tests on every root's files, and `tests.coverage` and the mutation engine count a line a dependent root's test ran as covered, so that test also runs against the line's mutants. Without a per-test map each root keeps its own tests only, and each `coverage.*`, `mutant.survived`, and `mutant.uncovered` finding there says so: evidence `own_root` names the root, and the action ends "(own tests of `<root>` only; no per-test map)" ([ADR-179](../adr/CUPEL_DECISION_179.md), [ADR-194](../adr/CUPEL_DECISION_194.md)). The Rust and Go per-test maps measure a root's whole workspace: a test records the lines it runs in every crate of its cargo workspace (`--workspace`), and in every package of its Go module, or of each module its `go.work` uses (`-coverpkg`), so a sibling crate's integration test or a sibling package's test covers and kills a library's code ([ADR-202](../adr/CUPEL_DECISION_202.md)). They do not reach separate roots: a file of another root counts only its own root's tests.

## Mutation testing

`tests.mutation` scores a `mutation-outcomes` fact, which the mutation engine makes from the `mutation-sites` every language produces, the coverage report, and the baseline. The engine runs each mutant with the same runner as the baseline; the check only counts and reports, so another producer of the fact feeds the same check. For Java that producer can be PIT, through the [PIT plugin](plugins.md#the-pit-plugin). Coverage gates which mutants run, so a language without a `coverage` command skips `tests.mutation` as `unconfigured`, as it does `tests.coverage`.

- `mutant.survived` (fails the check): every test that ran against the mutant passed. The finding sits at the mutated site and names the change (`from`, `to`, `operator`), the tests that missed it (`covering_tests`, as a per-test map selected them; without one, `all_tests` is true and the list is empty, since every test ran: `explain` says "all tests (no per-test map)", [ADR-191](../adr/CUPEL_DECISION_191.md)), and the nearest test file. Write a test that fails on the mutant.
- `mutant.uncovered` (a note): no test runs the site, so its mutant was not run.
- `mutant.timeout` (a note): the mutant was not decided within its time cap, so its outcome is unknown. A mutant that ran the whole suite reached its timeout, which usually means it loops; a mutant whose selected tests ran one at a time could not run them all within `max_mutant_timeout`, and the finding names the slowest it did not complete (see Timeouts below). A test that hangs well inside its own cap kills the mutant instead ([ADR-160](../adr/CUPEL_DECISION_160.md)).
- `mutant.out-of-memory` (a note): the tests held more memory than the run's share of `max_mutant_memory` against the mutant and were killed, which usually means it loops while allocating.
- `mutant.equivalent?` (a note, confidence 0.3): the mutant survived but may behave exactly as the original — today, swapping `+`/`-` before a literal `0` or `*`/`/` before a literal `1`; flipping WebCrypto `subtle.importKey`'s `extractable` argument in a function that calls neither `exportKey` nor `wrapKey`; and changing the whole initializer of a `let`, `let mut`, or `:=` variable that the next statement naming it, at the same indentation in the same block, assigns again without reading it. It is left out of the score; suppress it once you agree.
- `mutant.slow-test-excluded` (a note): a test that took more than 60 seconds in the baseline was left out of every mutant run that per-test selection did not narrow (see Timeouts below); the finding names the test and its baseline duration.
- `mutant.flaky-test-excluded` (a note): a test that failed in the mutation slot with no mutant applied, though the baseline passed it (a timing test under parallel slots, a test that depends on its directory), was left out of every mutant's run, and the other tests scored the mutants ([ADR-219](../adr/CUPEL_DECISION_219.md)). Without that, a red unmutated run in the slot is an error, as it still is for a runner that cannot leave a test out.

The score `tests.mutation.score` is killed / (killed + survived + uncovered), 1 when nothing was scored: a change no test runs scores 0, so a score floor in a gate also asks for tests of it. Timeouts, mutants killed over their memory budget, unviable mutants, possibly equivalent survivors, and mutants a run cut short by `--budget` or `--timeout` did not reach are left out; a cut run is `partial`, with a note saying how many mutants it did not run. The other gate keys count mutants by outcome (`killed`, `survived`, `timeout`, `out_of_memory`, `uncovered`, `unviable` for one that did not build, `not_run` for one the cut left, `equivalent`) and say how many ran this time (`executed`) or were reused (`reused`), and how many of those ran behind a schemata build (`schemata`) or fell back to file copies (`fallback`).

How much is mutated follows the depth: at `standard` with `--changed` or `--base`, the functions the change touched; at `deep` and `exhaustive`, every function of the files in scope (the touched files with `--changed`, the tree without). Under a range, `tests.mutation` scores only the mutants in the functions the change touched (ADR-142). Test code is never mutated. Only the `default` operators run unless the language asks for more:

```toml
[lang.python]
mutation = { operators = "extended", jobs = 2, timeout_factor = 10 }

[lang.rust]
mutation = { strategy = "file-copy" }   # "schemata" (the default) or "file-copy"

[checks."tests.mutation"]
max_mutant_timeout = "5m"               # the longest any mutant's run may take; default 120s
max_mutant_memory = "6g"                # what the workers' runs may hold together; default 50% of physical memory
```

String and regex literals have their own operators, the `strings` group: a non-empty string used as a value becomes `""` (JavaScript, TypeScript, Python), and in a JavaScript or TypeScript regex literal each quantifier is edited (`*`↔`+`, a `?` removed, `{n,m}` to `{n}`) and each class too (a negated class un-negated, a range narrowed to its first member). They make many equivalent mutants (log messages, labels), so the group is off unless a language enables it, beside the extended set; neither `operators = "extended"` nor `--depth deep` turns it on ([ADR-180](../adr/CUPEL_DECISION_180.md), [ADR-187](../adr/CUPEL_DECISION_187.md)):

```toml
[lang.typescript]
mutation = { operators = "extended", strings = true }   # `strings = true` needs `operators = "extended"`
```

Mutation testing is expensive, so the engine stacks every saving it can. Before the first mutant, the baseline, the coverage report, and the per-test map come from [one run of the suite](languages.md#one-suite-run) where the toolchain allows, or from its cache when nothing changed. Then:

1. **Coverage gating.** A site no test runs, by the coverage report, is reported `uncovered` and never run. A site on a line the report does not instrument, in a file it does (code a `cfg` or build tag leaves out of the build, a constant the compiler evaluates), is not a mutant: no test can reach it.
2. **Reuse.** An outcome is stored in `.cupel/cupel.db` under a key of the function's source text, the site, the replacement, the tests that cover it, and the runner's version; a later run reuses it while that key holds, except a timeout, whose outcome is unknown. A second run with nothing changed runs no mutant; changing one test file reruns only the mutants that test covers.
3. **Per-test selection.** Where the language has a per-test coverage map from the baseline's runner (Go; Python with pytest-cov; Rust when cargo-nextest is the runner and cargo-llvm-cov is installed), a mutant runs only the tests that execute its line. The [one suite run](languages.md#one-suite-run) makes the map for Rust and Python at any depth. Otherwise, measuring a map from nothing happens at `--depth deep` and beyond; at `standard` the engine uses a cached map (see [`cupel tests --impacted`](usage.md#cupel-tests---impacted)) when refreshing it is cheap: one suite run for Rust and Python, at most 32 tests for Go. `cupel check --dry-run` says which, in the check's `needs`: `per-test-map(cached)`, `per-test-map(refresh 3 stale)`, or `per-test-map(deep)` when the depth leaves it out. Without a map a mutant runs the whole suite, or, where the language has several project roots, its own root's suite (ADR-194).
4. **Schemata (Rust).** Instead of one build per mutant, each Rust file is rewritten once with every mutant behind a run-time switch — the smallest whole expression around each site becomes `if cupel_mutant_id() == N { mutated } else { original }`, and a small reader of the `CUPEL_MUTANT` environment variable is appended to the file — so the file builds once and each mutant runs with `CUPEL_MUTANT=N`. Every line stays where it was. Before any mutant runs, each worker builds the rewritten file and runs its tests with no mutant selected; they must pass. Sites where an `if` cannot stand (patterns, `const` and `static` items, `const fn`, array lengths, macro arguments, attributes) and constants the compiler checks run as ordinary file copies. If the rewritten file does not compile, the sites on the lines the compiler names run as file copies and the file is rebuilt; if it still fails, the whole file runs as file copies. Nothing is lost either way: outcomes are the same under both, which the tests check on the Rust fixtures. The check reports how many mutants ran each way (`schemata`, `fallback`) and a note for each reason a mutant fell back. Other languages build per mutant (Go's builds take a fraction of a second; see [ADR-005](../adr/CUPEL_DECISION_005.md)).
5. **Overlays.** Mutants run in copies of the tree in the repository's `.cupel/work/slots/`, which `.cupel/.gitignore` keeps out of version control, one per worker (half the cores, at most four), kept between runs so builds stay incremental: files are cloned (macOS) or hard-linked, what `.gitignore` ignores is shared through symlinks except the runner's build directory (`target/` for cargo), and the mutated file is a private copy. Mutants of one file run concurrently; files run one after another. The copies stay there between runs, out of reach of the operating system's cleanup of temporary directories, and go with the repository; a run that is stopped (the budget, Ctrl-C) puts the original files back. Removing `.cupel/work/slots/` frees the space at once, and the next run rebuilds what it needs. `cupel doctor` reports how much they hold (`doctor.mutation-slots`).
6. **Timeouts.** File copies are timed by one **unmutated baseline** per run: before the first file copy, the first worker runs the whole suite once with no mutant, rebuild included, and that time sets every file copy's timeout. It is stored in `.cupel/cupel.db` by a suite hash over the test IDs and test files, every file under the runner's project roots that `.gitignore` does not ignore (what a test loads lies among them), the runner's command, its version, the test threads per worker, and Cupel's version, so a later run reuses it and runs no baseline while none of those changes ([ADR-185](../adr/CUPEL_DECISION_185.md)). A Rust file built as schemata is timed by its own schemata build's validation instead. A mutant's whole run takes at most `max_mutant_timeout` (default two minutes, under `[checks."tests.mutation"]`, overridable per language).
   - **A narrowed mutant** runs its selected tests one at a time, fastest first by their baseline durations, those the baseline did not time last ([ADR-160](../adr/CUPEL_DECISION_160.md)). It stops at the first test that decides it.
     - Each test gets ten times its baseline duration (`timeout_factor`), at least two seconds, plus the runner's start-up for one test, which the worker measures once per file.
     - A test that fails kills the mutant. So does a test that runs past its own cap when it normally finishes in under a quarter of it: a hang, named in the mutant's `hung`.
     - When the tests cannot all run within `max_mutant_timeout` for slowness, the mutant is a `timeout`. Its outcome is unknown, it is left out of the score, and its `mutant.timeout` note names the slowest tests it did not complete. A stored timeout is never reused, so the next run tries again.
     - A mutant of a function nearly every test runs is killed in seconds by its fastest failing test, however slow the rest.
   - **A mutant that per-test selection did not narrow** runs its tests as one run under ten times the timing run (the baseline, or for schemata the validation), at least two seconds and at most `max_mutant_timeout`, so a mutant that makes a loop endless costs at most the cap, however long the suite. Such a mutant that per-test selection did not narrow runs the whole suite, and a test slower than 60 seconds in the baseline is left out of that run (and of the timing run) where the runner can leave a test out, with one `mutant.slow-test-excluded` note per test; mutants whose covering tests the map selected run them however slow. A mutant only that test would kill then survives, so the note is worth reading beside the survivors.
7. **The machine's share.** The workers together never run more test processes than the machine has cores: each run (the timing run and every mutant) gets an equal share of the cores as the runner's parallelism, where the runner takes one (`cargo test` and `cargo nextest` `--test-threads`, and their build jobs with it; `go test -p`/`-parallel`; Jest and Vitest `--maxWorkers`; pytest, unittest, Surefire, and `clojure.test` keep their own). Each run also gets an equal share of `max_mutant_memory` (default half of physical memory, under `[checks."tests.mutation"]`, as a size like `6g` or a share like `50%`): a run whose processes hold more resident memory than that, sampled through `ps` about five times a second, is killed and is `mutant.out-of-memory`, left out of the score like a timeout. A mutant that honestly needs more (a large crate to link, a suite that spawns many processes) is reported with the remedy: raise the budget or lower `jobs`. Without the budget, a few mutants that loop while allocating can take the machine down before the timeout ends them ([ADR-148](../adr/CUPEL_DECISION_148.md)).
8. **Order.** Last run's survivors run first, then mutants of functions never run before, then the rest, so a time limit cuts the least informative work.

A Rust file's mutants cost one build per worker plus one test run each; outside Rust, each mutant costs an incremental build of what it changes plus the tests. The run's `--seed` reaches every mutant run. With `--events`, a long run is not silent: `tests.mutation` reports `progress` as each mutant finishes, `done` of `total` mutants (those reused or uncovered are done from the start) with `eta_ms`, the time left at the mean time of the mutants run so far.

Which tests a mutant's run can be narrowed to, or leave out, depends on the runner ([ADR-147](../adr/CUPEL_DECISION_147.md)); a mutant is narrowed only with a per-test map from the baseline's runner:

| Runner | Runs one test alone | Per-test map | Leaves a slow test out |
|---|---|---|---|
| `cargo-nextest` | every test (a `trybuild` test is one test) | yes | yes |
| `cargo-test` | none: the whole workspace, each integration binary whole | no | no (libtest reports no durations) |
| `go test` | each `Test` function, by name | yes | yes, by name in every package |
| `pytest` | each node ID and file | yes | yes |
| `unittest` | each dotted ID | no | no |
| `jest`, `vitest`, `node --test` | test files | no | no |
| Maven, Gradle (Surefire) | classes and methods | no | no |
| `clojure.test` | each var and file | no | no |

With a runner that has no map, every mutant runs the whole suite; with one that cannot leave a test out, a slow test stays in each such run and the cap bounds it. For a Rust repository, `[lang.rust] runner = "cargo-nextest"` gives per-test durations, selection, and exclusion.

On the Cupel repository itself (1377 tests, release build, 8-core Apple silicon, a quiet machine), a one-function change checked at `standard` with a warm cache takes about 10.5 minutes: one instrumented run of the suite (5.3 min) and the mutants (5.2 min, two mutants with sixteen covering tests each); an unchanged rerun takes 2 seconds.
