# CUPEL_DECISION_079: Coverage producers, report freshness, `tests.coverage`, and CRAP with coverage

**Date:** 2026-10-14 · **Status:** accepted · **Phase:** P3.2

## Context

ADR-067 gave `CoverageMap` its payload (version 1: `files[{file, lines[{line, hits}], branches: null | [{line, branch, hits}]}]`) so `static.crap` could be tested over hand-built maps, but nothing produced one. P3.2 adds the producers (design §8.7: a format parser plus an invocation per tool), ingestion of existing reports "when fresher than the sources (mtime and content hash)", the check `tests.coverage`, and CRAP from real coverage. The design and plan leave open:

- what each format's numbers mean in the payload (LCOV and Cobertura say "branch" differently, JaCoCo and Cobertura have no counts, Go's coverprofile has blocks rather than lines, and every format spells paths its own way);
- which command a coverage producer runs, and when it may run one at all: running coverage runs the test suite, and `static.crap` (`quick`) *wants* `CoverageMap`, so a quick run could start a full instrumented test run;
- what "fresher than the sources" compares, and against which sources;
- how `tests.coverage` says `branches: unavailable` — `CheckResult` has no free-text field;
- how a golden can show CRAP with known coverage when the coverage tools are missing on one machine and present on another (CI installs them all, this machine has some);
- whether a red suite under coverage is exit 4.

## Options

**The command.** (a) Each producer builds its own command line, as runners do (ADR-076), and runs whenever its tool is on `PATH`. (b) Each producer runs the `[lang.<id>] coverage` command the repository configured (which `init` already writes, per launcher: `uv run`, `pnpm`, `npx`), and is `unconfigured` without one. (a) means any `cupel check` at the default depth in any repository with `go` or `pytest` on `PATH` starts an instrumented test run nobody asked for, and the fixture repositories' survey and matrix goldens would depend on which tools the machine has. (b) makes coverage opt-in through the same key `doctor` already probes and runs it the way the project runs it.

**Freshness.** (a) Compare the report's mtime with the covered files' mtimes. A test added or changed is not a covered file (Go and llvm-cov exclude test files), so a stale map would keep reporting a symbol uncovered after its test was written — the agent loop would never converge. (b) Content hashes of every file under the project root, recorded when Cupel ran the tool; mtime only decides which files need rehashing. (c) Ask git. Fixture copies and many CI checkouts have no history worth trusting.

**The note.** (a) A finding kind `coverage.branches-unavailable`: visible, but it is not about code, it counts toward `next_actions`, and the plan says the *result* notes it. (b) `notes: [string]` on `CheckResult`, always emitted as ADR-013 requires: every golden and the design's example envelopes gain `"notes": []`. (c) The same field, omitted when empty: no existing envelope changes, at the cost of one optional property in an emitted type.

**Deterministic goldens.** (a) Accept tool-dependent goldens and let the stale-golden rule tolerate unavailable pairs; `static.crap` is always supported, so its golden would still differ by machine. (b) Commit, in the coverage fixtures, the cache a real coverage run left behind; a fresh cache makes the producer `Ready` without its tool, so every machine ingests the same real report.

**Exit 4.** (a) Coverage producers need `TestResults`, so the scheduler's baseline (ADR-076) refuses a red suite with exit 4 before coverage runs. That runs the suite twice per run and makes `tests.coverage`'s support depend on the runner's tool as well, which reintroduces machine-dependent goldens. (b) A coverage run that exits non-zero yields no map: the producer reports why and fails, so no coverage score or CRAP is computed from a red suite, and exit 4 for coverage arrives with the mutation engine (P3.4), which needs `TestResults` anyway.

## Decision

1. **Payload unchanged: `CoverageMap` version 1** (ADR-067). Files sorted by path, `/`-separated and relative to the repository root; lines sorted, each instrumented line once. `hits` is the execution count where the format gives one (LCOV, Istanbul, coverprofile) and 1 or 0 where it gives only covered or missed (Cobertura conditions, JaCoCo). `branches` is `Some` exactly when the report measured branches for that file (an LCOV record with a `BRDA` line, a Cobertura line with `condition-coverage`, an Istanbul `branchMap`, JaCoCo `mb`/`cb`); `None` otherwise — coverprofile always, llvm-cov's `BRF:0` without `BRDA` too. A branch is `(line, index on that line, hits)`. `CoverageMap::branches_measured()` is whether any file has `Some`. **Version rule:** bump `VERSION` when a field is renamed, removed, or retyped, when `hits` or a branch changes meaning, or when path normalization changes, because stored maps (the store's `coverage` index, P3.3's per-test maps, mutation coverage gating) would be read wrongly. Adding a format, a producer, or a tool does not bump it.
2. **Parsers** live in `cupel_adapt::coverage`, one function per format, format-only (no process, no file access): `parse_lcov`, `parse_cobertura`, `parse_istanbul`, `parse_coverprofile`, `parse_jacoco`, each `fn(&str) -> Result<CoverageMap, ReportError>` with paths exactly as the report writes them, and `parse(&str)` that recognizes the format from the text. Producers then make paths repository-relative (`CoverageMap` paths absolute under the directory the tool ran in are stripped; relative ones are joined to the project root; files outside the repository are dropped) and Go's import paths are mapped through the module path in `go.mod`. Several records for one file merge; a line's hits add up across records.
3. **Producers** (`cupel-adapt/src/coverage/`, one module per tool, IDs from the toolchain table): `tool.cargo-llvm-cov`, `tool.go-coverprofile`, `tool.pytest-cov`, `tool.coverage-py`, `tool.vitest-coverage`, `tool.jest-coverage`, `tool.c8`. Each needs `ProjectInfo` and runs once per project root of its language. It runs the configured `[lang.<id>] coverage` command through `sh -c` in the root, with `{out}` replaced by a report path under `.cupel/cache/coverage/<producer>/<entry>/` (the entry is named by a hash of the root's path, so two languages sharing a root — JavaScript and TypeScript — run the tool once and the second ingests); a command without `{out}` writes the tool's default report (`coverage/lcov.info` for vitest, jest, and c8), which the producer copies into the cache. The report's format is recognized from its text, so a command may ask for any of the five formats. **Availability:** `Ready` when a fresh report can be ingested (rule 4); otherwise `Unconfigured { key: "lang.<id>.coverage" }` when no language it serves configures a command; otherwise `MissingTool` when its program (`cargo-llvm-cov`, `go`, `pytest`, `coverage`, `vitest`, `jest`, `c8`, the last three also from the root's `node_modules/.bin`) is missing; otherwise `Ready`. `detected` holds when a runner the toolchain row pairs it with is detected (or pinned with `runner`). `tool()` names the program and its version command, so `doctor` requires and versions the coverage tool of every configured language whose checks need `CoverageMap`.
4. **Freshness and ingest.** After a run, the producer writes `sources.json` beside the report: the root, the directory the tool ran in, the report's hash, and the blake3 hash of every file under the root (skipping hidden entries, paths a `.gitignore` inside the root ignores, the root's `skip_dirs` and the tool's own output directory, and `[scope] exclude`; ignore files above the root, the user's global one, and `.git/info/exclude` do not count, so freshness is the same on every machine). A cached report is **fresh** when the same walk finds exactly the recorded files with the recorded hashes and the report is unchanged; a file whose mtime is not newer than `sources.json` is trusted without rehashing, so a fresh check on an unchanged tree is a walk of `stat` calls. A report at the tool's default location with no matching record (the developer ran the tool) is fresh when its mtime is newer than every file under the root. A fresh report is parsed instead of running anything. Anything else reruns the command.
5. **A red or broken coverage run** (the command exits non-zero, or leaves no readable report) yields no `CoverageMap`: the producer emits one `coverage.run-failed` finding (check `coverage`, severity `warn`, action `fix_bug`, evidence `dir`, `command`, `exit_code`, `output` tail) and fails, so `tests.coverage` reports `error` and `static.crap` scores nothing. Exit 4 is not wired to coverage in this step.
6. **`tests.coverage`**, version 1, tier 2, cost `standard`; needs `Symbols`, `CoverageMap`; wants `NormTree` (finding IDs) and `TestConventions` (test code is not scored; `nearest_test_file` hints). A symbol's lines are its instrumented lines after its first line, or its first line alone when nothing after it is instrumented: a declaration line runs when the definition is evaluated (Python's `def` on import), not when the function is called, so counting it would call an uncalled function covered. A symbol is scored when it has such a line. `coverage.uncovered-symbol` (warn, `write_test`): no instrumented line of the symbol ran; evidence `lines` (instrumented), `covered` (0). `coverage.uncovered-branch` (info, `write_test`): the symbol ran but some branch inside it never did; evidence `branches`, `uncovered`, `lines` (the lines of the uncovered branches). Branch findings are computed only when the map measured branches for the symbol's file; when it measured none at all, the result carries the note `branches: unavailable`. Metrics: `line` (covered share of the scored symbols' instrumented lines; the score, unit `line_ratio`), `branch` (covered share of their branches, only when measured), `lines`, `branches`, `uncovered` (symbols); per symbol, `uncovered_lines` ranks in `survey`. Status `fail` with an uncovered symbol.
7. **`CheckResult.notes`**: a list of short notes, omitted when empty, so every envelope without notes is unchanged. It is the one exception to ADR-013's "every property is emitted": its schema property carries `x-cupel-optional` and is left out of `required`. The scheduler suffixes each language's notes with ` (<lang>)` when it combines languages (ADR-064).
8. **`static.crap` version 3**: with a `CoverageMap`, CRAP from real coverage as ADR-067 specified, with coverage measured over the symbol's lines as in rule 6; without one, ADR-067's behaviour is unchanged. The version bump records that results change for the same configuration (ADR-048's consequence).
9. **Goldens.** The coverage fixtures (`repos/coverage/<lang>/`, linked as `repos/tests.coverage` and `repos/static.crap`) configure `[lang.<id>] coverage` and commit the `.cupel/cache/coverage/` a real run of each tool left there, so every machine ingests the same real report. The matrix harness verifies each pair with its support in the repository the pair runs on (`Registries::fixture_pairs`; support is per repository, and a fresh report is part of it), and serves a check's wants only from a ready producer, as a run does; `describe matrix`, computed outside any repository, still shows `tests.coverage` as `unconfigured`. A test fails, naming the files, when a committed cache is no longer fresh; regenerating it means deleting the cache and running `cupel check --only tests.coverage` in the fixture with the tools installed.

## Consequences

- Coverage never runs uninvited: a repository without `[lang.<id>] coverage` sees `tests.coverage` skipped `unconfigured` and `static.crap` without CRAP, as before, and the shared fixture repositories' goldens do not depend on installed tools. `cupel init --write` writes the key, so new repositories get coverage by default.
- Cupel's own `cupel.toml` configures `cargo llvm-cov`, so `make dogfood` runs the whole workspace under coverage where `cargo-llvm-cov` is installed and skips it as `unavailable` elsewhere (CI's dogfood job does not install it).
- The command runs through `sh`, which assumes a Unix shell, as Cupel's CI does.
- A test-only change invalidates the map, because every file under the root is a source for freshness; a README edit does too. Precision there is not worth a stale map.
- P3.3 reuses the parsers for per-test profiles (`parse_lcov` per test run). P3.4 can add `TestResults` to a coverage producer's needs, or gate mutation on the baseline directly, to make a red suite exit 4.
- `CheckResult` gained a field that is absent unless a check notes something; envelopes without notes are byte-identical to before, and a reader must treat a missing `notes` as empty.
