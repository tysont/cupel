# CUPEL_DECISION_142: A range's scope is the symbols its changed lines touch

**Date:** 2026-10-21 · **Status:** accepted · **Phase:** P9.F2

## Context

Design §6.4 orders the scopes `--symbols ⊂ --paths ⊂ --changed/range ⊂ tree`, and the glossary calls a scope "the set of files/symbols a run considers". ADR-040 resolved a range to its changed files and put every symbol of those files in scope; ADR-077 §5 added the changed lines of each file (`ChangedLines`, `git diff -U0`), which ADR-080 hands only to producers through `Focus::changed`, so the mutation engine mutates the changed lines while every check rules on whole files. A `none` rule in `[gate.changed]` therefore fails on whatever a touched file already held: `static.clones` reports a pair that existed at the base when one member's file changed, `tests.coverage` reports an uncovered function the range never touched, and every P9 branch's changed-gate dogfood failed on findings it did not write (P9.4's alone reported 21 pre-existing clone findings and four uncovered functions; follow-up item 18).

Checks already narrow by the scope: `Scope::includes` is how `static.complexity`, `static.crap`, `static.dead-code`, `tests.coverage`, `tests.quality`, `tests.assertion-density`, `tests.mutation`, `gen.property`, and `meta.oracle-independence` pick the symbols they report, and `static.clones` reports a group when any member is in scope. What a range's scope holds is the question.

## Options

**Narrow the scope's symbols to those the range touched.** The scheduler, which already resolves `Scope.symbols` per language (ADR-041), keeps a symbol under a range only when one of its file's changed lines falls within its span. Every check that honors the scope rules on the range with no change of its own; facts stay per file (producers still parse whole files, so a clone of a touched function in an untouched part of the same file is still compared), and a finding outside the range is not reported, exactly as a symbol outside `--symbols` is not. `scope.symbols` counts the touched symbols, which is what design §6.4's "a `--changed` scope with no changes … `scope.symbols: 0`" implies.

**Report every finding and flag those outside the range.** A finding gains a field (say `in_range`) and the gate's `none` counts only flagged ones. The envelope keeps the findings of the untouched code, which an agent cannot act on in this change, every renderer and the finding schema change, and metrics (`tests.coverage.line`, `static.crap.max`) still measure whole files, so a rule on a metric still fails on code the range did not touch.

**Rule on the delta: compare each finding with the base side.** Run each check on the base versions of the changed files too (ADR-056's base tree) and report only findings new since the base. It handles code a change made worse without touching it, but doubles every check's cost on every `--changed` run, needs a stable identity for each finding across sides (ADR-131's symbol matching covers symbols, not clone groups), and the base side's facts lack the head's coverage and mutation runs.

**Post-filter findings by location.** Drop findings whose `location` misses the changed lines. A clone group's `location` is one member, so a group whose touched member is not the first is lost; diff-native checks (`tests.weakening`, `static.api-surface`) locate findings at base-side lines or deleted files; and a filter in the CLI duplicates what `Scope` already means.

## Decision

1. **Under a range, the symbols in scope are those the range touched.** `cupel_core::scope::touched(changed, symbol)` holds when one of the changed line ranges of `symbol.file` overlaps `symbol.span` (`start <= span.end_line && span.line <= end`). A file in scope with no entry in `ChangedLines` is one git does not track yet (`git diff` lists no untracked file, while the range's changes list it as added), so every line of it is new and all its symbols are touched. `--symbols` with a range intersects: a selected symbol the range did not touch is out of scope.
2. **Where.** The scheduler's symbol resolution (`symbols_in_scope`) applies it, after the selectors, from `Job::changed`, so `CheckCtx::scope`, `Outcome::symbols` (`scope.symbols`), and `--dry-run`'s targets all see the narrowed set. No check, producer, fact, schema, or renderer changes.
3. **Findings outside the range are left out, not flagged.** That is what a scope means in design §6.4: a narrower scope reports less, as `--paths` and `--symbols` do, and the envelope stays the list of things the change should fix. To see a touched file's other findings, run `--paths FILE` (or the tree gate, which grades them).
4. **A clone pair or cluster belongs to the range when at least one member was touched** (`static.clones` already reports a group with any member in scope). **A per-symbol finding belongs to it when its symbol was touched.** A test case is a symbol (ADR-054), so `tests.quality` and `tests.assertion-density` rule on the test cases the range touched.
5. **Checks whose findings are not about symbols keep file granularity**, because their finding has no span that says what caused it: `static.deps` reports a cycle among the modules of the changed files (a cycle a new import closes is located at whichever module the cycle starts from, not at the import); `static.analyze` keeps an analyzer's diagnostics in the changed files (a diagnostic on an untouched line can be caused by a touched one, such as an unused-import warning after the last use is removed); `spec.contracts` and the generative checks report what running the code found. Narrowing these by line would hide findings the range caused; Cupel's tree holds none of them, so the changed gate does not fail on old ones. `tests.weakening` and `static.api-surface` read the base side (ADR-056) and already rule on the range's difference.

## Consequences

- The changed gate fails on what a change wrote or touched: a pre-existing clone pair, an uncovered function, a long function, or a weak test in a file the change edited elsewhere is no longer reported, and the tree gate still grades it. P9.5–P9.7's open items about pre-existing clone and coverage findings close.
- A finding a change causes on a symbol it did not touch is not reported by the changed gate: a function left uncovered because the change removed its only test, or left dead because the change removed its last caller in another symbol. The tree gate on `main` reports both; a change that wants them reported runs `--paths` on the affected files.
- Metrics under a range are measured over the touched symbols: `tests.coverage.line` is the touched functions' line ratio, `static.complexity.cyclomatic_max` the touched functions' maximum, `static.clones.pairs` the pairs with a touched member. A `base` rule (ADR-130) on a range compares these with the base files measured whole, which widens P9.1's open item 2 from mutation to every per-symbol metric; Cupel's `[gate.changed]` has no `base` rule.
- `tests.mutation` scores only the mutants of touched functions (it filters by `Scope::includes`). At `standard` that is what the engine mutates (ADR-080); at `deep` the engine still mutates every function of the changed files (ADR-129), so under a range the mutants of untouched functions are run and stored but not scored. Narrowing the engine's deep plan to the touched functions would save that time; the engine is `cupel-mutate`'s, and its plan already reads `Focus::changed`.
- Measured blast radius: of the suite's range tests, only the symbol-matching fixture moves (its head commit leaves `describe` untouched, so `scope.symbols` and `static.complexity`'s score `n` fall from 6 to 5); every other `--changed`/`--base` test adds or rewrites whole functions, so its touched set equals its files' symbols.
- `scope.symbols` of a `--changed` or `--base` envelope counts touched symbols, so the range goldens' and the CLI tests' symbol counts fall where a change leaves symbols of its files untouched.
- `--base A --head B` reads the lines `git diff A B` changed while producing from the working tree (ADR-056 §6), so with a working tree not at `B` the spans and the lines can disagree; that is the same limitation ADR-056 records, now affecting scope too.
