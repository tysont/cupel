# CUPEL_DECISION_138: External dogfood: the method, the repository selection criteria, and the triage rubric

**Date:** 2026-10-21 · **Status:** accepted · **Phase:** P9.9

## Context

P9.9 (track (c) of the owner's P9 ruling) grades other people's code: two mid-size open-source repositories per native language (Rust, Python, TypeScript) and one per adapter language (Go, Java, Clojure), `survey` and `check --depth deep` on each, every finding triaged, a false positive fixed as a check bug with a fixture case, and a report per repository in `docs/dogfood/`. Three agents run it in three groups (Rust and Go; Python and Java; TypeScript and Clojure), so the numbers they report are comparable only if they choose repositories the same way, run Cupel the same way, and call a finding true or false by the same rule. The brief (`docs/plan/p9/p9.9-external-dogfood.md`) fixes the outline; it leaves open what "mid-size" is measured as, how a deep run is bounded on a repository that is not Cupel, what a verdict means for each kind of finding, how a repository with hundreds of findings is triaged one row per finding, and how a rate is computed when a check is not a yes-or-no detector.

## Options

**Bounding the run.** (a) `--budget`, as Cupel's local dogfood does (ADR-129): comparable wall time per repository, but the budget's choice depends on recorded costs the first run does not have, so a fresh clone leaves out whatever the estimate puts last, and the report grades a different set of checks per repository. (b) No bound: every check `deep` selects runs to the end, `tests.mutation` over every function of the tree. On a 20k-line crate that is thousands of mutants; at P9.0's measured rate (12 mutants in 23 minutes at a high load, faster idle) a run could take many hours. (c) No bound on the checks, one bound on the run (`--timeout`): a run cut by the clock keeps an arbitrary prefix of the mutation work, which is (a)'s problem again. (b) is the only option that grades the same checks everywhere; one repository at a time, with the engine's slots at half the cores and at most four, keeps the machine usable while it runs.

**Counting a measurement.** Most checks are not detectors that are right or wrong about a defect: `complexity.high` reports a number over a threshold, `crap.watch` a score in a band, `clone.pair` a similarity. Reading "false" as "a maintainer would not refactor it" makes the rate a poll of taste; reading it as "the reported fact about the code is wrong" makes it a measure of the check, which is what a check bug is.

**Triaging volume.** One row per finding, each verified by hand, is the brief's rule and is affordable for tens of findings; a repository with hundreds of `crap.watch` or `mutant.survived` findings makes it either a rubber stamp or weeks of work. Verifying each row mechanically where the verdict follows from a recomputation (the cyclomatic count from the source, a surviving mutant from its diff and the suite), and by hand where it does not, keeps one row per finding with a reason that was checked.

## Decision

1. **Selecting a repository.** A library (an application only when no library fits) of 10k–60k lines of the language counted over its source and test files, excluding generated code and vendored trees; a permissive license (MIT, Apache-2.0, BSD, ISC, or a dual of them); a commit on its default branch in the last year; and a test suite that passes from a fresh clone with the tools `make dev-setup` installs at their pins (Rust 1.92 stable with the nightly Miri needs, Go 1.23, and so on) with no service, container, credential, or toolchain download (a `go.mod` asking for a newer Go, a `rust-toolchain.toml` pinning another channel, or an `.nvmrc` above the pinned Node rules a repository out). Prefer, among those that qualify, the widely depended-on ones, whose maintainers' standards are known. Record the url, the commit, the line count, the license, and the suite's wall time from a cold build.
2. **Running.** The clone is a fresh directory under the agent's scratchpad, never inside Cupel's tree, and is untrusted data: only its documented test command runs, through Cupel. Cupel is the branch's `cargo build --release` binary, run from the clone's root with the dev environment (`eval "$(make -s dev-env)"`). The commands, in order, one repository at a time and never while a `make dogfood` of the same agent runs: `cupel init` (its `cupel.toml` kept as written; any key set by hand is recorded with the reason), `cupel survey --depth deep --no-install --format json`, then `cupel check --depth deep --no-install --format json`. No `--budget`, `--only`, or `--skip`: the deep set runs whole; a check that cannot run on the repository reports so itself (`skipped` or `error`), and that is a result. No `--timeout` either: the time the deep set takes on the repository is part of the result, and each run's wall time and each check's `duration_ms` are reported; `survey` and `check` on one tree share the fact store, so the second reuses the suite runs and mutation outcomes the first made. Envelopes under 200 KB are committed beside the report (`docs/dogfood/<owner>-<repo>/`); larger ones stay in the scratchpad and the report summarizes them.
3. **What a verdict means.** A finding is **true** when what it states about the code is correct (the value, the location, the symbols, the mutant's survival) and the code is what the check says it grades; **false** when it is not, which is a check bug, whatever a maintainer would do about it; **disputed** when the statement is correct but whether it applies is defensible either way (an intentionally invalid file under a compile-fail test directory, a clone a maintainer keeps on purpose, a dependency cycle the language idiom makes normal). The maintainer's view decides the action ("what a maintainer would do first"), not the verdict. Per kind:
   - *Measurements* (`complexity.high`, `nesting.deep`, `params.many`, `function.long`, `crap.high`, `crap.watch`, `clone.pair`, `clone.cluster`, `dep.*`, `test.*` of `tests.quality`, `tests.assertion-density`, `coverage.uncovered-symbol`, `dead.*`): true when the value recomputed from the source (or from the coverage report the run made) matches and is past the threshold; false when the value is wrong, the location or symbol is wrong, or the code is outside what the check grades (generated code, a macro body counted as the macro's caller, test code graded as production, a symbol reached by a path the check does not see).
   - *Executions* (`mutant.*`, `test.flaky`, `property.*`, `fuzz.*`, `race.*`, `ub.*`, `contract.*`, `perf.*`): true when it reproduces: the mutant's diff applied to the clone leaves the suite green (`survived`) or no test reaches it (`uncovered`); a property or fuzz input fails when replayed; false when it does not reproduce or the mutant does not compile; `mutant.equivalent?` is disputed by definition unless the mutant is shown equivalent or not.
   - *Wrapped tools* (`analyze.*`, `footprint.*`, `dep.vuln`, `dep.license`): true when the tool reports it at the configured strictness and Cupel's location and rule match the tool's; false when Cupel's normalization is wrong; disputed when the rule is one the repository's own configuration turns off.
   - *Cupel's own diagnostics* (`lang.parse-error`, a producer's `tool.*` notice): true when the file really does not parse as the language, or the tool really is missing or failed; false when the file is valid and the grammar is wrong.
4. **One row per finding.** Every finding has a row: id, check, kind, location, verdict, one sentence of reasoning, action. Rows whose verdict follows from a recomputation are verified by a script in the agent's scratchpad that recomputes the value from the clone (the reasoning names what was recomputed); every other row, and a sample of at least ten rows (or all, if fewer) of each mechanically verified kind, is checked by hand. The table is in the report, grouped by check, one line per row, however long.
5. **The rate.** Per check and repository, `false / (true + false)` with both counts shown; disputed rows are listed and counted apart. A check with no finding on a repository has no rate (`—`), not 0.
6. **A false positive.** The smallest excerpt in that language that reproduces it becomes a fixture case in `crates/cupel-fixtures` (a file in the language's fixture repository with its `inventory.toml` entry, or a case in the check's test), the test fails first, the check or fact producer is fixed, the goldens are regenerated additively, and the repository is run again to show the finding gone and every true finding still there. The gate, the renderers, and the daemon are not changed by P9.9.
7. **The report.** `docs/dogfood/<owner>-<repo>.md`, in the brief's section order; each group adds a `**P9.9 — group N**` bullet to the plan's P9 Notes. A later group changes this rubric only with an amendment to this ADR that says why.

8. **The check bugs group 1 fixed** (each with its fixture case; the report names the finding that showed it):
   - *A Go test that hands its `t` to a helper asserts* (`tests.quality`, `tests.assertion-density`; spf13/cobra). Go's idiom for a shared assertion is a function of the package that takes the test's `*testing.T` and fails it (`expectSuccess(output, err, t)`, `check(t, got, want)`, marked `t.Helper()`), often in another `_test.go` file, where a per-file query cannot see its body. Go's `tests.scm` captures a call of a plain function name with `t`, `b`, or `tb` among its arguments as an assertion, except a name starting `new`/`New` (a constructor that sets up), and marks its name `@assertion.helper` (below): it asserts as the helper does when a test file of the package in scope defines it (`check(t, out, "x")`, a `strings.Contains`, stays weak; `checkExact(t, got, want)` is equality), and as `helper` (custom, strong, as Rust's `assert_…` convention) when none does; and `t.Run(name, f)` with a named function or method value `f` (`t.Run(name, tc.test)`), whose assertions are in `f`. A subtest written as a literal is already part of its case. Testify's `assert.Equal(t, …)` and gomock's `NewController(t)` are package-qualified and unchanged.
   - *Go's standard-library equality, compound conditions, and switch cases pin values* (`tests.quality`; spf13/cobra). Only a top-level `got != want` guarding a failure call read as equality; `!reflect.DeepEqual(got, want)` (and `bytes`, `slices`, `maps`, go-cmp `Equal`), `ok && got != want`, and a `switch { case got != want: t.Errorf(…) }` read as a bare failure (truthiness, weak), so a test pinning its output was `test.weak-assertion`. They are now `equal` (equality, strong); `!errors.Is(err, ErrX)` (and `As`) is `error-is` (throws, strong, as testify's `ErrorIs`); `case err != nil:` is `no-error` as its `if` form is.
   - *A Rust test that calls a helper of its file, or asserts inside a macro's arguments, asserts* (`tests.quality`, `tests.assertion-density`; serde-rs/json). Only `assert_…`-named helpers counted, so `test_encode_ok(&cases)`, `check_number(1u32, 5)`, and every test written as `test_stream!(data, |stream| { assert_eq!(…) })` read as asserting nothing. `tests.scm` gains a language-neutral capture, `@assertion.helper`, on the name a call is made by: when that name is a function of the same file that is not a case and holds an assertion, the call asserts with the class of the helper's first strong assertion, else its first (an assertion a pattern already captured at the call takes that class, else one is added; one level, a helper's own helper calls are not followed); when the file defines no such function, a call that is already an assertion takes the class of an asserting function of that name in another file of the same directory in scope, which the producer resolves once every file is read (`QueryProducer::finishing`). Rust captures every call by plain name with it, and captures an `assert…` name followed by its argument tokens inside a macro's token tree or a `macro_rules!` repetition as an assertion. Rust does not follow a helper of another file (each integration test is a crate of its own, and a plain call is no assertion until a helper of its file makes it one); its `assert_…` naming convention still covers that case.
   - *A mutant on a line the coverage tool does not instrument is not a mutant* (`tests.mutation`; serde-rs/json). The engine called every site with no hit `uncovered`, so a site in code the configured build leaves out (`#[cfg(feature = "arbitrary_precision")]` bodies, a `const` the compiler evaluates) was reported "no test runs it" and counted against the score (ADR-141). `CoverageMap` already documents an absent line as not executable code: a site whose lines the map does not instrument, in a file it does, is left out of the plan (`CoverageMap::instruments`). A file the map does not hold at all stays as before, since for V8 and coverage.py that is a module no test loads; a Rust file that only a disabled feature compiles (`mod raw` under `feature = "raw_value"`) is therefore still reported, and the report lists those rows as disputed. A Python site on a continuation line of a multi-line statement (coverage.py records a statement's first line) is left out too, where it was wrongly `uncovered` before.
   - *Rust's `#[path = "…"] mod name;` loads the file it names* (`static.dead-code`, `static.deps`; serde-rs/json). The resolver did not read `#[path]` (ADR-068 left it out), so serde_json's `#[path = "core.rs"] mod imp;` declared an unresolved `imp` and every export of `src/io/core.rs` was `dead.export` "no import resolves to it". `imports.scm` gains `@import.path` on the attribute's string beside a body-less `mod`, and the resolver resolves such a declaration to that file in the declaring file's directory.
   - *A switch arm that guards a failure call is not test logic* (`tests.quality`; spf13/cobra). `test.logic` offsets `if` branches by the case's assertions (each guards one failure call, ADR-069) but counted every switch or match arm as an unguardable alternative, so Go's `switch { case got != want: t.Errorf(…) }` table tests read as logic. Case arms now count with branches, which the assertions offset; conditional expressions and exception handlers stay alternatives.
   - *A test file roots its module* (`static.dead-code`; rust-itertools/itertools). The module pass (ADR-058) reported every function of a file no import reaches unless one of its symbols is a root; a test runner reaches a test file by its path, and a file whose cases a macro writes (`must_use_tests! { … }`) or whose entry point a macro writes (criterion's `criterion_group!`/`criterion_main!`) has no root symbol. `static.dead-code` now wants `TestConventions`: a file it calls a test file roots its module (the symbol pass still runs over the file's symbols). Rust's test globs add `**/benches/**/*.rs`: Cargo builds each bench, like each integration test, as a crate of its own that only `cargo bench` runs, so it is test code to every check, not a library module nobody imports.

9. **The check bugs group 2 fixed** (each with its fixture case; the report names the finding that showed it):
   - *A Python test that calls an asserting helper of its file, or a method of its harness, asserts* (`tests.quality`, `tests.assertion-density`; PyCQA/pyflakes). Python's unittest idiom for a shared assertion is a method of a `TestCase` base class in a harness module of the test package (pyflakes' `self.flakes(source, *expected)`, which ends in `self.assertEqual`), and a pytest or unittest file's own helper is a plain function or a method of the case's class; only `self.assert…` and `assert` statements counted, so every test written through its harness read as asserting nothing. Python's `tests.scm` captures a call by plain name and a `self.name(…)` call (other than `self.assert…`) with `@assertion.helper`, which resolves as §8 says within the file. Where a call names no asserting function of its own file, a language whose tests share helpers by directory (`[tests] directory_helpers = true`: Go, whose package is its directory, and Python, whose test package's harness sits beside its tests) takes the class of an asserting function of that name in another file of the same directory in scope; a call that names none stays as its own patterns read it (a Python call asserts nothing, a Go call handing `t` stays `helper`). This is the condition §8's Go rule needed ("a call that is already an assertion"), stated as the language's property; Rust does not set it.
   - *A comprehension in a test is not test logic* (`tests.quality`; more-itertools/more-itertools, PyCQA/pyflakes). `test.logic` (ADR-054, ADR-069) counts a case's loops and its branches beyond its guards, and Python's `decisions.scm` makes a comprehension's `for` and `if` clauses loops and branches, as cyclomatic complexity should; so `self.assertEqual(mi.first(x for x in range(4)), 0)` and `expected = [(i, c) for i, c in enumerate(s)]` read as a test with a loop, though the test's statements run in one straight line and the clause only computes a value (88 of 167 `test.logic` findings on more-itertools, 7 of 12 on pyflakes). `Decision` gains `expression` (`Decisions` version 3): a loop or branch that is a clause of an expression computing a value, marked by a generic capture `@expression.clause` on the decision's node (Python: `for_in_clause` and `if_clause`; no other grammar has such a clause, since a closure passed to `map` or `filter` is not a decision); its cyclomatic and cognitive weights are unchanged, and `tests.quality` leaves it out of a case's loops and branches. A conditional expression stays an alternative, as ADR-054 counts it.
   - *A statement that holds an assertion is not setup* (`tests.quality`; PyCQA/pyflakes). `test.duplicate-setup` (ADR-055) compares the first `setup_statements_min` statements of a file's tests, assertions included, so tests written through an asserting harness (`self.flakes(source, *expected)` three times; `checker = self.flakes(…)` followed by the same inspection of its result) were one group whose "setup" no fixture can hold (7 of 8 findings on pyflakes). The statements a test may share are those before its first statement whose span holds one of the case's assertions; that statement is what follows them. A statement the producer gives no span is never known to hold one. The count of shared statements compares statements by shape, as the grouping does; it compared them with their spans, so it never went past `setup_statements_min`.
   - *A decision inside a lambda is not test logic* (`tests.quality`; more-itertools/more-itertools). A test that hands the code under test a key or step function written as a lambda (`mi.iterate(lambda x: 3 * x + 1 if x % 2 == 1 else x // 2, 42)`, `key=lambda state, number: (number if state == 'CT' else 2 * number)`) read as a test with an alternative, though its statements run in one straight line and the conditional runs when the code under test calls the function. A generic capture `@expression.function` on a function written as an expression (Python: `lambda`) marks every decision inside it `expression` (`Decision.expression` now covers any kind there, a comprehension's clauses as before); its weights are unchanged and `tests.quality` leaves it out of a case's loops, branches, and alternatives. A conditional expression the test itself evaluates stays an alternative.
   - *mypy reads a module's stub, not its implementation* (`static.analyze`; more-itertools/more-itertools). more-itertools types its API in stubs beside untyped modules (`more.py` and `more.pyi`, checked against each other by `stubtest`). Cupel handed mypy every Python file in scope, so mypy `--strict` graded the untyped `more.py` (211 `no-untyped-def`) and, since an explicitly named module shadows its stub, read every test's call into the package as a call to an untyped function (952 `no-untyped-call` in `tests/test_more.py`); over the test files alone it reads the stubs and reports 58. mypy's file list now leaves out a `.py` file with a `.pyi` beside it: the stub is the module's types for every importer, and the implementation is the stub's business, not mypy's. ruff still lints every file.
   - *A Java test that calls an asserting helper method of its class asserts* (`tests.quality`, `tests.assertion-density`; apache/commons-cli). A JUnit test that checks through a private method of its class (`checkOption(Option.builder("a").get(), "a", …)`, whose body is `assertEquals`) read as asserting nothing. Java's `tests.scm` captures a method called by plain name or on `this` (other than JUnit's `assert…` and `fail`) with `@assertion.helper`, which resolves within the file as §8 says; Java does not set `directory_helpers` (a helper of another class is reached by a qualified name or inheritance, which the capture does not follow).
   - *A function a module's top-level code calls is an entry point* (`static.dead-code`; PyCQA/pyflakes). ADR-034 roots the functions an `if __name__ == "__main__":` guard calls; a setup script runs its body unguarded (`setup(version=get_version(), long_description=get_long_description())`), and nothing imports it, so both functions were `dead.export`. Python's `api.scm` makes a function an entry point when a module-level expression statement calls it directly, as a positional or keyword argument of a call, or as an assignment's value: a module runs that code whenever it runs, so for a module nothing imports it is the script's body, as the guard's is.

## Consequences

- The three groups' rates measure the same thing: how often a check states something false about real code. A finding a maintainer would ignore but that is correct counts as true; the reports say so in "What a maintainer would do first", where taste belongs.
- A deep run on a whole tree can take hours, mostly in `tests.mutation` and `conc.race`; the reports record each check's time from the envelope so the cost is visible.
- Repositories that need a newer toolchain than the pins are out of reach until the pins move; the selection says which candidates were ruled out and why.
- The mechanical verification scripts live in a scratchpad, not the repository: what is kept is the reasoning in each row.
- Cross-file helper classes are resolved over the files in scope, so a `--changed` run that touches a test but not the package's helper file reads the helper call as custom and strong.
- Left open by group 1, each with its reason in the reports: a Go `case` expression lies in no cover-profile block, so per-test selection misses tests that evaluate it without entering the arm (two false survivors on cobra); a file the coverage report does not hold may be one the build leaves out (`//go:build windows`, a `cfg`-gated Rust module, `build.rs`) or one no test loads, and only a producer that knows its tool reports every compiled file could tell them apart; a helper that asserts through a macro of another file (serde_json's `test_parse_err!`) is not followed; and `survey`'s protect-first list ranks test functions first, since they have no mutation score or coverage of their own (a ranking defect, not a finding).
