# CUPEL_DECISION_131: Symbols matched across refs by similarity, with set-level deltas

**Date:** 2026-10-19 · **Status:** accepted · **Phase:** P9.2

## Context

Everything that compares two refs matches by identity. `delta.rs` compares runs by `FindingId`, whose symbol part is the structural hash of ADR-025; `tests.weakening` pairs tests by file, name, and repeat, then by name in another file (`tests_weakening::matches`); `static.api-surface` pairs items by path and signature; `tests.mutation` reuses a stored outcome by a cache key over the mutated function's source. The hash survives a rename and a move, since names and positions are not hashed, but not an edit: a function renamed and edited, split in two, or merged from two reads as removed plus added. Its findings show as resolved plus new, a split function's metrics have no predecessor, and `tests.weakening` reports a renamed test with a changed body as deleted. The owner's P9 ruling asks for symbols matched across refs by similarity (the `NormTree` fingerprints and Jaccard similarity of ADR-050, name and signature similarity breaking ties), one-to-many and many-to-one, and deltas computed at the set level: a base finding with a finding of the same check and kind on any of its successors is neither resolved nor new, and a metric compared across a split is compared against the set (sum for counts, weighted mean for scores) with evidence naming the set.

Open: the similarity criterion and thresholds, where matching lives, which consumers use it now, where the per-symbol values of the reference run come from, and what the envelope shows.

## Options

**Where matching lives: a `SymbolMatches` fact.** Cacheable, and inspectable with `explain`. But a fact is produced by one producer from one tree (the producer contract, design §8.3.3): matching needs both sides of a range at once, which no producer sees, so it would need a two-sided producer kind the scheduler does not have. Caching buys little: matching compares only the symbols whose hash changed, in the changed files.

**Where matching lives: a core function over two sides' `Symbols` and `NormTree`.** `cupel_core::matching` takes the candidates of each side and returns the matches; the scheduler calls it for a range run, where it already keeps a fact store for the base side (ADR-056), and a check that already reads both sides (`tests.weakening`) calls it on its own facts. Nothing is cached and `explain` cannot show a match on its own, but every match that changes a delta is shown in the envelope.

**Similarity criterion.** Jaccard similarity alone cannot see a split: each part shares a fraction of the whole's fingerprints, so the part and the whole are dissimilar though the part was cut from the whole. Containment (the shared fingerprints over the smaller set) sees parts in a whole, and a whole in its sources for a merge, but a small tree is contained in many unrelated large ones. So: containment to propose candidate pairs, each symbol keeping its best candidate; the connected components of the kept pairs as matches; and the Jaccard similarity of the two sides, each side's trees joined under one root, to accept or reject a match and to drop a member whose removal raises it.

**Consumers.** Deltas (findings and metrics); `tests.weakening`'s test pairing; `static.api-surface`'s renamed items; mutation outcome reuse.

**The reference run's per-symbol values.** The envelope carries scope-level scores only. Per-symbol measurements reach the store's `metrics` table, whose per-symbol rows (design §8.8, ADR-045 §5) nothing filled, or the comparison is confined to findings.

**Envelope.** A `matched_from` on each finding carried across a match, or the evidence on `checks[].delta`. A field on `Finding` is constructed in sixteen places across the crates and every check another branch adds; `Delta` is constructed in two, and the delta is where the comparison is already reported.

## Decision

1. **Matching** is `cupel_core::matching`: `candidates(&Symbols, &NormTree)` joins a side's symbols with their trees by key; `across(base, head)` matches the base symbols whose hash the head lacks with the head symbols whose hash the base lacks (a symbol whose hash both sides hold is the same symbol); `match_symbols(removed, added)` matches any two lists. The fingerprints are ADR-050's, from `cupel_core::similarity` (moved from `static.clones`, which now imports it).
   - **Candidates:** two symbols are candidates when one holds at least `CONTAINMENT` = 0.8 of the other's fingerprints (the smaller set's share; ADR-050's clone threshold is 0.82). Trees under `MIN_NODES` = 30 nodes take no part: a smaller tree is mostly its signature and one statement, and the real-binary weakening test showed two unrelated one-assertion Go tests (22 and 19 nodes) containing each other.
   - **Ties:** each symbol keeps its best candidate on the other side by containment, then Jaccard similarity, then name similarity (the Dice coefficient of the names' letter pairs, ignoring case), then an equal parameter count, then the same file, then the earlier position.
   - **Matches:** the connected components of the kept pairs: one to one (rename, move, edit), one to many (split), many to one (merge). A member whose removal makes the match's two sides more similar is dropped, repeatedly; a match whose sides, each taken as one tree, are under `SET_SIMILARITY` = 0.5 Jaccard similar is no match. A match's similarity is reported to three decimals.
   - Matching is quadratic in the removed and added symbols, which are those of the changed files.
2. **The scheduler** matches under a range only: for each language in scope, both sides' `Symbols` and `NormTree` (produced as checks would, base-side producer findings dropped as ADR-056 drops them) give `Outcome::matches`. A language where either side lacks either fact has no matches. A run without a range has none, so `--against` a baseline in a tree run compares by identity as before.
3. **Deltas** (`deltas_matched(current, against, &Matching)`; `deltas` is the identity case): for each match, each check, and each finding kind, when the reference run has findings of that check and kind on the match's base symbols that the current run lacks, and the current run has findings of that check and kind on its head symbols that the reference lacks, all of them are carried: neither resolved nor new. A finding of another kind, or on a symbol outside every match, is new or resolved as before.
4. **Per-symbol metrics over a set:** every run records its checks' per-symbol measurements (those with a symbol hash, ADR-062) in the store's `metrics` table with `Store::record_metrics`, and `Store::symbol_metrics(run)` reads a run's back. For each match and each per-symbol metric the current run measured on its head symbols and the reference stored for its base symbols, the set's value on each side is the sum over the members measured, or, for a metric the check declares a score (`Check::averages`, default false: `static.crap`'s `crap` and `tests.quality`'s `mock_density`), the mean weighted by each member's tree size in nodes. Today's counts are `cyclomatic`, `cognitive`, `survivors`, and `uncovered_lines`.
5. **Envelope** (smallest additive change): `run.baseline`, `summary`, and `Finding` are unchanged in shape. `Delta` gains `sets`, an optional property absent when empty (`x-cupel-optional`, as ADR-079 and ADR-111 made `notes` and `settings`): one `SetDelta` per match on which the check had findings carried or a per-symbol metric compared, with `base` and `head` (the symbols, as a finding's `symbol`), `similarity`, `findings` (`base`: the reference's carried IDs, `head`: the current run's), and `metrics` (each name to `{base, head}`). A set exists only where the check has a delta, that is, a score in both runs. A carried finding's `new_since_baseline` is false and `summary.new`/`resolved` exclude it.
6. **Consumers now:** deltas (3–5), and `tests.weakening`: after pairing by file, name, and repeat and by name elsewhere, the base tests left unpaired are matched with the unpaired head tests by `match_symbols` over the symbols of the same file and name whose spans overlap the test's (version 2; it now needs `Symbols` and `NormTree` on both sides, which every language with `TestFrames` has). A one-to-one match is compared as a pair; a split or merge compares the sum of the set's assertion counts, reports `assertion.removed` and `matcher.loosened` on the first head test, and `test.skipped` on each head test skipped when no base member was. A test without a symbol of its name (an ECMAScript `it(...)` callback) is paired by name only, as before.
7. **Deferred, with reasons.** `static.api-surface`'s renamed items: a renamed public item breaks its callers whatever its body, so the finding stands; matching would only add the old name to the evidence, and `ApiSurface` items (types, constants) have no `NormTree`. Mutation outcome reuse: an outcome is the verdict of running one mutant of one exact source; reusing it across a similar but different function would report a verdict nobody ran. Matches in a tree run against a stored baseline: they need the reference commit's trees, which a run without a range does not parse; `--base <ref>` gives a run them. `meta.traceability` and `meta.oracle-independence` read `tests.weakening`'s name pairing to find added tests and keep it.

## Consequences

- A rename, move, edit, split, or merge no longer churns `summary.new` and `summary.resolved` under `--changed --against`, and the delta says which symbols were matched, how similar they are, which findings were carried, and how each per-symbol metric compares across the set.
- Carrying is per check and kind, not per finding: a split that turns one `mutant.survived` into three carries all four, so the count of survivors on the set (its `survivors` metric) is where a change in number shows.
- Every run writes its per-symbol measurements to the store, so `explain <check>` lists them after the check's score (the per-symbol metrics `last_run_for_check` already returns).
- A matched pair below the thresholds reads as removed plus added, as before; the thresholds are constants, not settings, until a repository shows a need to tune them.
- `tests.weakening` reports fewer `test.deleted` findings for tests renamed with an edit; a test rewritten so much that it no longer matches is still reported deleted.
- A plan step, a `describe` of matches, or a match cache are not provided; adding a fact kind later would let `explain` show matches without changing the deltas.
