# CUPEL_DECISION_141: Uncovered mutants in the score, red suite runs uncached, mutation slots reclaimed, aliased imports bound

**Date:** 2026-10-21 · **Status:** accepted · **Phase:** P9.F1

## Context

Four follow-up items (plan, P9 Notes, "P9 — follow-up list") are engine questions the earlier ADRs answered one way and the dogfood showed to be wrong.

1. **Item 16.** `tests.mutation.score` is `killed / (killed + survived)`, "1 when nothing was scored" (ADR-080, kept by ADR-129 §5 when the combining bug was fixed). A mutant no test runs is `uncovered` and left out, so a change whose sites no test reaches scores 1.0 and passes `tests.mutation.score >= 0.80`; only the changed gate's `tests.coverage` `none` catches it, and a gate with only the mutation rule passes untested code. The P9.1 gate test had to be rewritten around it.
2. **Item 17.** A joint suite run (ADR-084 §6) is cached with the record of the tree whenever it completed and made its coverage, a red one included ("a cached red baseline is returned as recorded"). P9.2's baseline failed because the disk was full; the red result was reused by every later run until `.cupel/cache/suite` was deleted, since the tree, which is all the cache key records, had not changed.
3. **Item 19.** Mutation slots (ADR-080 §8: `$TMPDIR/cupel-mutate/<hash of the repository path>/<lang>/<n>`) persist so builds are incremental. Each production removes the slots of repositories whose path no longer exists (a marker file, `repository`, names the path), but nothing bounds the slots of repositories that do: four slots of a workspace the size of Cupel are about 52 GB, two finished runs in two live worktrees held 87 GB and filled the owner's disk twice, and a deleted worktree's slots stay until some other mutation run starts. A production stopped by the budget or cancelled can leave a slot holding a mutated or schemata copy of a file, which the next sync replaces with a hard link (Linux) dated as the tree's file, older than the slot's build, so cargo does not rebuild it.
4. **Item 20.** `References` (ADR-135 §3) binds a name through an import when the statement lists the name and the name is the last segment of the edge's specifier. That holds for Python, Rust, and Java, whose resolvers join the module and the name into the specifier, but not for ES modules, whose specifier is the module (`./math.js`): an ES named import resolved only where its name happened to equal the specifier's last segment. The JavaScript fixture's `square` (`import { square } from "@ledger/shapes"`, a package whose index re-exports it) resolved only because the next line, `import { square as side } from "@ledger/shapes/square"`, ends in `square`; the index defines no `square`, and nothing followed its re-export. And `ImportEdge.names` (ADR-133) holds the imported name, not the local alias, so `import { square as side }` leaves every use of `side` unresolved; Python's `from x import a as b` the same.

## Options

**The score (item 16).** (a) Keep the ratio and rely on `tests.coverage`: the gate's floor is then vacuous for untested code, and `survey`'s protect-first ranking (ADR-132) cannot tell an unprotected function from a protected one. (b) Count uncovered mutants as missed: `killed / (killed + survived + uncovered)`, what PIT ("mutation coverage"), mutmut, and cargo-mutants report; a scope with nothing to mutate stays 1. (c) A second metric for the covered score and a gate on both: two numbers where one says what the rule means. Timeouts and unviable mutants stay out under every option: a timeout is usually a kill the runner could not observe, and an unviable mutant tests nothing.

**Red suite runs (item 17).** (a) Never reuse a run that is not green: a red baseline reruns on every run until it is fixed, which costs one suite run per attempt while the user is fixing it anyway, and exit 4 already stops everything that depends on it. (b) Reuse a red run while the tree and the environment are unchanged: the environment (free disk, tool versions, network, other processes) has no record that tells a disk-full failure from a real one, so (b) needs a fingerprint that would still miss the case that happened.

**Reclaiming slots (item 19).** (a) Age only: removes abandoned checkouts after N days but nothing within a day, when the disk filled. (b) Total size only: bounds the disk, but keeps a slot of a checkout abandoned months ago as long as it fits. (c) Both, never touching the slots of the repository being graded or of one being graded right now: needs to know which slots are in use. A marker's age cannot say that (a production may run for 90 minutes on one file); a lock held for the production can. Measuring sizes by walking every repository's slots at every production start costs seconds per 10 GB, at every production of Cupel's own suite; a size recorded by each production at its end costs one walk of its own slots.

**Consistency after a stop (item 19).** (a) Restore every file a slot rewrote when a file's run ends in an error. (b) Make the next sync correct whatever the slot holds: a slot file whose bytes differ from the tree's is replaced by a copy dated now, never a hard link, so every build tool sees the change. (a) alone misses a killed process; (b) alone leaves the slot holding a mutant between runs.

**Local names (item 20).** (a) `ImportEdge.bindings` with every `(imported, local)` pair: repeats `names` on every edge of every module-graph golden. (b) `ImportEdge.aliases`, only the names bound under another name, absent when empty: additive and small. And binding by `names` instead of the specifier's last segment fixes the ES case as well as the alias, with the same result for the languages whose specifier already ends in the name. A name bound from a file that only re-exports it (an ES index, a Python `__init__` listing it in `__all__`, Rust `pub use`) is then unresolved unless the re-export is followed; following re-export edges by name, until a file defines it, keeps "never guesses" (each hop is an edge the module graph resolved).

## Decision

1. **The mutation score counts uncovered mutants** (option b). `tests.mutation`'s `score` is `killed / (killed + survived + uncovered)`, 1 when the scope has no such mutant; the result's `Score.n` is that denominator, so languages combine weighted by it (ADR-129 §5 unchanged). Each function's `mutation_score` (ADR-132) is the same ratio over its mutants, absent when it has none of the three, so a function whose mutants are all uncovered scores 0 and ranks first for protection. Possibly equivalent survivors stay out as before (ADR-004), as do timeouts and unviable mutants. The check's status is unchanged: `fail` with a survivor; an uncovered mutant stays an info finding (`mutant.uncovered`). ADR-080's score and ADR-129 §5's "1 when nothing was scored" are amended.
2. **A suite run is cached only when it is green** (option a). A joint suite run (ADR-084 §6) is written to `.cupel/cache/suite` only when every invocation completed, it made its coverage (and its per-test map, for a joint that makes one), and no test failed or errored (`TestResults::is_green`, ADR-075); the per-test entry it writes follows the same rule. A red or incomplete run is made again by the next run. The entry's version is 2, so an entry written before this decision, possibly red, is run again once. ADR-084 §6's "a cached red baseline is returned as recorded" is amended.
3. **Mutation slots are reclaimed** (options c, and a with b).
   - *Records.* Each repository's slot directory (`$TMPDIR/cupel-mutate/<hash>/`) holds `repository` (its path, rewritten by every production, so its modification time is the slots' last use), `size` (the bytes of its slots, written at the end of each production by walking them: regular files' lengths, links not followed), and `lock`, which every production of the repository holds (a shared lock) until it ends.
   - *Rule.* When a production claims its slots, every other repository's directory whose `lock` it can take exclusively (none of its productions is running) is removed when its repository path is no longer a directory, or its last use is more than **7 days** old; then, while the recorded sizes of every repository's slots total more than **32 GiB**, the least recently used of the other unlocked repositories is removed. The repository being graded is never removed. A directory with no `lock` file was made by a production that takes no lock (an earlier Cupel, which may be running now): the gone and idle rules apply to it, not the size rule. Seven days: the owner's branches live for hours to a day, and a checkout untouched for a week is abandoned or cheap to rebuild once (one build per slot) against tens of gigabytes. 32 GiB: the slots of the repository being graded plus one or two small ones; one large checkout's slots alone exceed it (Cupel's are ~52 GB), so a second large checkout's idle slots go first, which is the case that filled the disk. A repository with no `size` (slots made before this decision, or a killed production) is measured once and the size written.
   - *Consistency.* When a file's mutants end in an error (the budget, a cancellation, a reference run that is not green), every slot the file used gets the original file back, written fresh, before the error goes on; and a sync replaces a slot file whose bytes differ from the tree's with a copy dated now, so a build in the slot sees it even after a killed process. A slot is consistent when its next sync makes it reproduce the tree for every build tool.
   - *Report.* `cupel doctor` adds `doctor.mutation-slots` (info, `review`) when the slots directory holds any repository: the total size, and each repository's path, whether it still exists, its size, and its last use.
   ADR-080 §8 is amended.
4. **Imports bind their local names** (option b). `ImportEdge` gains `aliases`: `{name, local}` for each name the statement imports under another local name (`import { square as side }`: `square`, `side`; a default import `import d from`: `default`, `d`; Python `from x import a as b`), absent when empty. `imports.scm` gains `@import.alias` on the local name paired with an `@import.name` (Python), and a list captured as `@import.names` gives each child's `alias` field (ES import specifiers; an `export … from` list binds nothing locally and records none). `References` binds through an edge to a file, not a declaration: each name in its `names` under its local name, looked up among the target's functions by the imported name; an edge with no `names` binds as before (its specifier's last segment when the statement lists it, or path imports). When the target defines no function of that name but has a `re-export` edge to a file naming it, the edge is followed (each file once) until a file defines it; the reference resolves `imported` to that file. ES named imports now resolve; the other languages' bindings are unchanged but for aliases and names reached through re-exports. ADR-133 (`ImportEdge`) and ADR-135 §3 are amended.

## Consequences

- Every mutation golden with uncovered mutants moves its `score`, `metrics.score`, and per-function `mutation_score`; `survey`'s protect-first ranks over them move. A gate floor on `tests.mutation.score` now fails a change whose sites no test runs; Cupel's own changed gate measures it from P9.F1 on (plan notes).
- A red baseline costs a suite run on every attempt until it is green; an environment failure no longer outlives the environment.
- A checkout's mutation slots are rebuilt after a week idle, or sooner when another checkout needs the room; a production holds a lock file open for its duration. The cap and the age are constants; a machine that needs other values is a follow-up with a reason.
- `size` is the apparent size: on APFS the slots' cloned sources share blocks with the tree, so it overstates them slightly; build directories dominate it.
- Rust `use a::b as c` and Clojure `:refer`/`:as` are not captured as aliases; ES namespace imports (`import * as ns`) bind members, which stay unresolved.
