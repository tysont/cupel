# CUPEL_DECISION_020: The `Writer`, run records, the event stream, timeouts, dry runs, and seeds

**Date:** 2026-10-10 · **Status:** accepted · **Phase:** P0.7

## Context

Plan step P0.7 builds the run infrastructure every later verb stands on. Design §6.1 rules 4, 6, and 7 say every verb has a side-effect-free `--dry-run`, nothing is written outside `.cupel/` without `--write`, and every run records its seed; §6.3 defines `--events`, `--timeout`, `--seed`, and `--write`; §6.8 sketches the plan a dry run returns; §7.4 gives the event lines; §8.8 says `.cupel/` is gitignored except `suppressions.toml`; §8.9 step 7 says a timeout cancels outstanding work and emits `partial`. None of them says:

1. How "nothing outside `.cupel/`" is enforced, what counts as outside (`..`, symlinks, absolute paths), or what `--write` permits.
2. Which runs write a run record, what it holds, and what happens when it cannot be written.
3. Where a relative `--events` path is resolved, whether the events file is itself subject to the `.cupel/` rule, and whether a dry run, which promises zero side effects, still streams events.
4. What cancellation looks like before there is an async runtime or a scheduler, and how a timeout can be exercised before any slow work exists.
5. The envelope shape of a dry-run plan, how `would_write` diffs are produced, and what `--dry-run` means for a verb with no side effects (`describe`) or no behavior yet.
6. Where the random default seed comes from, and whether `run.started` needs a time crate.

## Options

For (1): check paths lexically (cheap, but `.cupel/link → /etc` and `.cupel/../src` slip through or are judged by spelling), or resolve the deepest existing ancestor with the file system and judge the real location. For `--write`: permit only the repository, or permit any path. The repository-only variant breaks `baseline export /tmp/x.json`, which the user asked for by name.

For (2): write a record only for verbs that succeed (the record then cannot explain failures), or for every run of a verb that resolved its root (failures are recorded too). On a write failure: fail the run (an unwritable `.cupel/` would turn every verb into an error), or report on stderr and keep the verb's envelope.

For (3): exempt the events file from the `.cupel/` rule because the user named it (simple for agents, but `--events src/main.rs` would overwrite source without `--write`), or route it through the same rule (one rule, no exception; agents use `.cupel/…`, `stderr`, or `--write`).

For (4): pull in `tokio`'s `CancellationToken` (an async runtime nothing needs yet), or a small shared flag plus deadline in core that work polls. For the slow task: a hidden test-only verb or flag (visible in the parser), or an environment variable read once after parsing, like `CUPEL_DEBUG_PANIC` (ADR-018 §7).

For (5): emit the §6.8 fields at the top level (breaks ADR-013's fixed key set), or one nullable typed field per ADR-018 §1. For diffs: have each writing verb compute its own, or have the `Writer` record what it would have written in a dry run, so any verb that writes through it gets `would_write` for free.

For (6): a `rand` dependency, `std`'s `RandomState` (randomly keyed per process, not documented as a random source), or the 80 random bits of a fresh ULID, which the `ulid` crate already draws from `rand`'s OS-seeded generator.

## Decision

1. **`Writer` (`cupel_core::Writer`) is the only way Cupel writes files.** It holds the canonical repository root, an *area* in which writes are always allowed (`<root>/.cupel`), and whether `--write` was given. A target path is resolved against the root when relative, then judged by where it really lands: the deepest existing ancestor (found with `symlink_metadata`, so a dangling symlink counts as existing) is canonicalized, a dangling symlink is refused, and the remaining, non-existent components are appended with `.` dropped and `..` popping. The path is allowed when that location is inside `<root>/.cupel` (compared against the root joined with `.cupel`, so `.cupel` itself being a symlink elsewhere is refused), or anywhere at all when `--write` was given. Refusal is `Error::Write(WriteError::Outside { path })`, naming `--write`. I/O failures are `WriteError::Io` with the path and the OS message. Parent directories are created as needed.
2. **Layout.** `.cupel/runs/<run-id>.json` (run records), `.cupel/cache/` (fact and parse caches, P1+), `.cupel/work/<run-id>/` (a run's scratch area), `.cupel/cupel.db` (P2.2), and `.cupel/.gitignore`, whose content is `*` and `!suppressions.toml`: everything in `.cupel/`, itself included, is ignored except suppressions, the convention of tool caches such as pytest's. The `Writer` writes that file whenever it creates `.cupel/`, so a repository that never ran `init` does not see run records in `git status`; `Writer::gitignore` writes it on demand for `init` (P0.8). `Writer::scratch(run)` returns a `Writer` whose area is `.cupel/work/<run-id>/` and which never writes outside it, `--write` or not; that is the writer a check sees in `CheckCtx`. Producers get the run's writer with `--write` withheld (`Writer::confined`), so `ProduceCtx.writer` can fill `.cupel/cache/` but never touch the repository. Nothing deletes `.cupel/work/` yet; the step that first fills it (P3.4) owns cleanup.
3. **Run records.** Every invocation whose command line parsed, whose root resolved, and whose verb is anything but `describe` writes `.cupel/runs/<run-id>.json`: the complete, unpaged envelope as pretty JSON with a trailing newline, whatever the `--format`, including error envelopes (a usage error or a pending verb is still a run worth explaining). `describe`, `<verb> --describe`, and every `--dry-run` write none: `describe` is pure, and a dry run writes nothing. A record that cannot be written is reported on stderr (`cupel: could not write the run record: …`, also under `--quiet`, since nothing else would say so) and the envelope and exit code are unchanged; `doctor` (P0.8) is where an unwritable `.cupel/` becomes an actionable finding.
4. **Events.** `--events stderr` streams to standard error; any other value is a path, resolved against the repository root when relative (`./stderr` names a file called `stderr`). The file is opened through the `Writer`, truncated, and subject to the same rule as every write: outside `.cupel/` it needs `--write`, and refusal is a usage error (exit 2) whose subject and argument are `--events`. `cupel_core::JsonlSink` writes each event as one compact JSON line and flushes it, so readers see findings as they are discovered; the first write error stops the stream and is reported on stderr after the run. The events file is the requested output channel, not a side effect, so a dry run streams events like any other run. The events of one invocation are, in order: `plan` (for dry runs today; for real runs from the P2.1 scheduler), then `check.start`/`progress`/`finding`/`skip`/`check.end` as work happens (P2.1+), then exactly one `run.end` carrying the envelope's `status` and `exit_code`, emitted for every invocation that opened the stream, errors included. A command line that does not parse, or whose root does not resolve, opens no stream.
5. **Timeouts and cancellation.** `cupel_core::Cancellation` is a cloneable shared flag plus an optional deadline. `is_cancelled()` is true once `cancel()` was called or the deadline passed; `checkpoint()` turns that into `Error::Cancelled` for `?`; `wait(duration)` sleeps in slices of at most 10 ms, returning early (and `false`) on cancellation. `--timeout` parses with `config::TimeLimit` and sets the deadline to the invocation's start plus the limit, so time spent parsing and loading configuration counts. `CheckCtx.cancel` and `ProduceCtx.cancel` carry the token. Work that stops because of cancellation leaves its results in place; when any work was cut short the envelope's `status` becomes `partial` and its exit code 5, with every completed result still included (design §6.6). An envelope that is already an error keeps its error. Until the P2.1 scheduler exists, the only interruptible work is `CUPEL_DEBUG_SLEEP_MS=<n>`: read once after parsing, it makes every verb except a dry run wait `n` milliseconds on the run's token before its own work, and when the wait is cut short the verb still runs and its result is reported as `partial`. Like `CUPEL_DEBUG_PANIC`, it exists for tests and is absent from `describe`.
6. **Dry runs.** `Envelope` gains a nullable `plan: Option<RunPlan>`, set exactly when `status` is `plan`. `RunPlan` has `would_run` (`PlannedCheck { id, targets, est_ms, needs, note }`), `would_skip` (`PlannedSkip { id, reason, fact, lang, tool, see }`: the check result's `Skipped` object flattened beside the check ID, as in §6.8), `would_install` (`PlannedInstall { tool, command }`), `would_write` (`PlannedWrite { path, diff }`), and `est_total_ms`. The §6.8 sketch's `oracle` and `cases` join `PlannedCheck` with the generative checks (P5) that have them; its `scope` is the envelope's `run.scope`. A dry run's `Writer` records instead of writing: each `write` becomes a `PlannedWrite` whose `path` is relative to the root (absolute outside it) and whose `diff` is a unified diff (via `similar`, three lines of context, headers `a/<path>`/`b/<path>`, and `/dev/null` for a file that does not exist yet). `diff` is null for a write whose content is not known before the run (a run record, a cache entry); P2.1 lists those. A dry run of a verb that is not built yet is still `cli.not-implemented` (exit 2). `describe --dry-run` is a plan whose lists are all empty: `describe` would run nothing and write nothing. Each dry run emits one `plan` event with the planned check count and `est_total_ms`.
7. **Seeds.** Without `--seed`, `run.seed` is the low 64 of the 80 random bits of a freshly generated ULID (`cupel_core::random_seed`), with 0 replaced by 1 so a drawn seed is never mistaken for "no seed". The ULID crate draws them from `rand`'s OS-seeded generator, which the build already contains for run IDs, so no dependency is added. The seed is not secret and is always echoed.
8. **`run.started`** keeps the dependency-free RFC 3339 formatter in `cupel-cli/src/run.rs`, which is tested against independently computed dates; no time crate is added until something needs to parse or do arithmetic on times.

## Consequences

- Every file Cupel writes passes one check, and a dry run of any verb that writes through the `Writer` reports exact diffs without verb-specific code; P0.8 `init --dry-run` gets `would_write` by writing `cupel.toml` and `.cupel/.gitignore` through a recording writer.
- Agents that want an events file outside `.cupel/` must pass `--write`; the usage error says so.
- Every non-`describe` invocation in a repository creates `.cupel/runs/`; integration tests therefore run the binary in a temporary directory rather than the crate directory.
- P2.1 emits `plan`, `check.*`, `progress`, `skip`, and `finding` into the sink the CLI already opens, polls `Cancellation` between targets, marks unstarted checks `skipped` with reason `timeout`, and relies on the partial rule above.
- `CUPEL_DEBUG_SLEEP_MS` stays as the exit-5 trigger in `tests/exit_codes.rs` even after real slow work exists, because it is deterministic.
