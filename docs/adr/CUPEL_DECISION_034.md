# CUPEL_DECISION_034: Python syntactic facts: visibility and `__all__`, normalization of receivers and docstrings, test idioms, API, and roots

**Date:** 2026-10-10 · **Status:** accepted · **Phase:** P1.2–P1.8 (python)

## Context

Python has no visibility keywords. Its conventions are a leading underscore (`_name`, "internal use"), class-private name mangling (`__name`), dunder protocol names (`__init__`), and the module's `__all__`, which defines what `from m import *` exports. Design §8.4.2 names "Python's implicit `self` scoping in normalization" as a construct queries cannot express; docstrings are documentation, yet syntactically a string statement. Pytest and unittest spell assertions as statements and methods, not macros. ADRs 024–029 fix the generic rules; this ADR records how Python maps onto them.

## Options

**Visibility levels.** (a) Two levels: underscore names private, everything else public. (b) Three levels matching what the names promise: public, internal (`_name`: importable by path, not part of the interface, PEP 8's "weak internal use"), private (`__name`, mangled to its class; and functions nested in a function body, which nothing outside can reach).

**`__all__`.** (a) Ignore it. (b) When a module assigns `__all__`, the names it lists are public and every other non-underscore name is internal; when it does not, every non-underscore name is public, which is exactly what `from m import *` exports and what PEP 8 says users may assume. Queries cannot express "not in a list", but the generic producers pick the earliest pattern per definition, so "listed → public" followed by "`__all__` present → internal" followed by the name rules expresses it.

**Receivers and docstrings in `NormTree`.** (a) Plain table normalization: `def f(self, x)` in a class and `def f(x)` with the same body differ by one parameter, and adding a docstring changes the hash. (b) A Python override that post-processes the generic tree: drop a method's leading `self`/`cls` parameter and a body's leading docstring, rehash. It needs no change to the generic normalizer and still passes the same inventory. Because `generic::register` would also register the table-driven `NormTree` producer, Python registers its generic producers itself, swapping in the override for `NormTree`.

## Decision

- **Visibility.** Dunder names are public; `__name` is private; `_name` is internal; a function or lambda bound directly in a function body is private; a module-level name in a module with `__all__` is public when listed and internal otherwise (underscore and dunder names keep their name rule). `__all__` is read when assigned a list or tuple of string literals before the definitions, as PEP 8 places it; `__all__ +=` and computed lists are not read.
- **Decisions.** `if` and `elif` are branches (`elif_clause` is the chain link under `if_statement`); `for`, `while`, and comprehension `for` clauses are loops; comprehension `if` clauses and `case` guards are branches; `and`/`or` are boolean operators; `x if c else y` is a ternary; non-wildcard `case` clauses are cases; `except` and `except*` are catches; `return` and `raise` that are not the body's final statement are early returns.
- **Normalization.** Identifiers are `$id`; numbers, strings (including f-strings, whose interpolations are part of the literal), `True`, `False`, `None`, and `...` are `$lit`; decorators, type annotations, and the return arrow are erased, so an annotated function and its unannotated twin normalize alike; word operators (`and or not in is`, `is not`, `not in`) are kept. The Python override then drops a method's first parameter when it is named `self` or `cls`, and the leading string statement of the symbol's body, and rehashes.
- **Mutations.** Equality covers `==`/`!=` and `is`/`is not`; boolean operators swap `and`/`or`; literals flip `True`/`False`; statement deletion replaces a statement by `pass` (an empty block does not parse); return values become `None`; negation wraps a condition in `not (…)`.
- **Test frames.** Cases are functions named `test*` (pytest functions, methods of `Test*` classes, unittest `TestCase` methods); a file containing a `TestCase` subclass is `unittest`, otherwise `pytest`. Assertion idioms: `assert a == b` equality strong; `assert a != b` equality weak; `assert x is None` equality strong; `assert x is not None` not-null weak; `assert a == pytest.approx(b)` equality strong; `assert x == snapshot` and `snapshot.assert_match` snapshot strong; bare `assert x` truthiness weak; relational and membership asserts custom weak; `pytest.raises` throws strong; unittest `self.assert*` by method name; `mock.assert_*` custom. Skips are `@pytest.mark.skip`/`skipif`/`xfail`, `@unittest.skip*`, and `pytest.skip()` calls. Mocks are `patch` decorators and context managers, `mocker.patch`, `monkeypatch.setattr`, and `Mock`/`MagicMock`/`AsyncMock` constructions. Setup is `@pytest.fixture` functions and unittest/pytest setup methods. Conventions: `test_*.py`, `*_test.py`, anything under `tests/`, and `conftest.py` are test files; a module `x.py` is tested by `test_x.py` or `x_test.py` beside it or anywhere under its project's `tests/`.
- **API surface.** Module-level public functions, classes (`Protocol` and `ABC` subclasses are interfaces), constants (upper-case names), variables, `type` aliases, and the public methods (and `__init__`) of public classes, under the same `__all__` rule as visibility. Signatures run from the parameters to the return annotation; parameter names are `_` except `self` and `cls`; a class's signature is its base-class list. Python declares no modules in source, so the `module` construct is not applicable.
- **Roots.** `main` is an entry point by name, and so is any function the `if __name__ == "__main__":` guard calls; dunder methods, `@pytest.fixture` functions, `pytest_*` hooks, and unittest/pytest setup and teardown methods are framework hooks.

## Consequences

- A conditional module-level definition (inside `if` or `try`) takes its visibility from its name alone, and a function nested inside a compound statement of a function body is classified by its name rather than as private; both are rare and stay visible in `Symbols`.
- Keyword arguments make Python parameter names part of a function's interface; ADR-029 normalizes them to `_`, so renaming a parameter does not change `ApiSurface`. A later fact version can keep names for Python if `static.api-surface` needs it.
- A function named `test*` outside a test file is reported as a test case; the query cannot see the file's path.
- `def f(self, x)` in a class and `def f(x)` with the same body share a hash, while `def area(self): return self.r` and `def area(c): return c.r` no longer do.
