# CUPEL_DECISION_135: A `References` fact, and `static.dead-code` decides per symbol

**Date:** 2026-10-20 · **Status:** accepted · **Phase:** P9.6

## Context

ADR-058 decided `static.dead-code` per module because no fact carried references: a private function nobody calls, in a file something imports, was never reported (the Rust fixture's `scale`), and an imported module kept every symbol in it live. The owner's P9 follow-up item 6 asks for a `References` fact for every language Cupel parses (the five launch languages, Java, and Clojure) and for the check to decide reachability per symbol: a symbol with no reference outside its own definition and no root by convention is `dead.symbol`, the module pass stays first, confidence is lowered where references are unresolved, and every rule that suppresses a finding is written down, since this check's false positives cost trust. Adding a fact kind needs an ADR (plan §2.5).

Open: what a reference is in a syntax tree, how far a producer resolves one without type information, which files the fact covers (a `--changed` scope holds the edited file but not its callers), how dynamic access shows, and which symbols the per-symbol pass leaves alone.

## Options

**What is recorded.** (a) Calls only. Misses a function passed as a value (`map(f)`, `QueryProducer::new(.., extract)`), named in a table, or named by a string a framework reads (`#[serde(default = "port")]`, `getattr(m, "name")`): each would be reported dead. (b) Every identifier, every member name, and every string literal whose text is a name, each a reference; plus the attributes, decorators, and annotations on a definition, which hand it to whatever processes them. Over-approximates (a local variable named like a function keeps the function live), which costs only missed findings.

**Resolution.** (a) None: a symbol is live when any reference anywhere has its name. Sound and simple, but a private `parse` in one file keeps every `parse` in the language live. (b) Full name resolution per language (scopes, types, traits, overloads): the language's compiler, out of reach of queries. (c) The two cases a syntax tree decides: a plain name with a definition of that name in the same file, and a plain name an import of the file binds; everything else (members, strings, names nothing in the file binds) stays unresolved and matches by name. A resolution never guesses: when the bound file defines no such name, the reference is unresolved.

**Coverage.** (a) The scope's files, like every other syntactic fact: under `--changed` a function's callers in unchanged files are invisible, and every `pub(crate)` helper of an edited file reads as dead. (b) Every file of the language in the repository (the walk's rules: `.gitignore`, `[scope] exclude`, the ecosystem's generated directories), whatever the scope; findings stay in scope. The extra parse is cached per file content.

**Dynamic access.** (a) Leave it out: a function reached by a computed name is reported at full confidence. (b) Record each computed access site with what it can reach (members of a value, or any name in a namespace), and lower the confidence of every finding such a site could reach. (c) Refuse to report in a language with dynamic access: no finding in Python or JavaScript at all.

## Decision

1. **Fact `References`** (`references`, version 1, syntactic, with a conformance inventory), appended to the catalog (ADR-123). `references`: one entry per reference, `{file, span, name, kind, from, target}`. `kind` is `name` (a plain identifier), `member` (a name reached through a value, type, module, or namespace: `x.f`, `T::f`, `m/f`, and every identifier inside a Rust macro's token tree, which the grammar does not structure), `text` (a string literal whose text is a name or a path of names; `name` is its last segment), `attribute` (an attribute, decorator, or annotation on a definition; `name` is its name as written), or `implicit` (a method the runtime calls by a name the language fixes, such as a JavaScript `constructor`). `from` is the innermost symbol containing the reference, `null` at module level. `target` is `local {symbols}` (definitions in the same file), `imported {file, symbols}`, or `unresolved`. `dynamic`: one entry per computed access, `{file, span, from, reach, text}`, `reach` being `members` (a computed member access: reaches methods) or `names` (a lookup by a run-time name in a module or namespace, or code evaluated from text: reaches any symbol). The fact covers every file of the language in the repository, not only the scope (Coverage (b)).
2. **Producer** `lang.<id>`, registered by each language next to its `ModuleGraph` producer because it calls the same resolver over the language's files. It reads `references.scm`: `@reference.name`, `@reference.member`, `@reference.text`, `@reference.attribute` with `@attribute.name`, `@dynamic.members`, `@dynamic.names`; one capture per node, the earliest pattern winning, as in `symbols.scm`. A definition's own name is not a reference. `tables.toml [references]` holds `inert` (attribute names that only instruct the compiler or a linter, which are not references), `implicit` (method names the runtime calls), and `path_imports` (§3).
3. **Resolution.** A `name` reference resolves `local` to the same file's functions and closures of that name (never methods, since a plain name does not call one in any of the seven languages but Java, whose methods stay unresolved); else `imported` to the functions and closures of that name in the file an import of the reference's file binds it from; else `unresolved`. An import binds the names its statement lists (Python's `from ledger.decide import parse_cents`), or, where `[references] path_imports` is set, the last segment of each path a statement that lists no names imports (Rust's `use crate::report::format::render`); the name must be the last segment of the edge's specifier, split on `/`, `.`, `:`, and `\`, and the edge must lead to a file and not declare a module. JavaScript and TypeScript imports list the names ADR-133's `ImportEdge.names` carries (`import { square } from "@ledger/shapes"` binds `square`; the imported name, so `import { square as side }` binds `square` rather than its alias `side`, which stays unresolved: follow-up item 20); Go, Java, and Clojure imports list no names the queries read (a Go or Clojure import binds a package or namespace, a Java import a type), so their plain names resolve only within their file. `attribute` and `implicit` resolve `local` to the definition they belong to. `member` and `text` are `unresolved`.
4. **`static.dead-code` version 2** needs `References` besides its four facts. The module pass of ADR-058 runs first, unchanged. The symbol pass then takes every symbol in scope the module pass did not report, and does not report it when any of these holds (each rule suppresses a finding):
   - it is a root for any reason (entry point, export, test, framework hook);
   - it is nested in another symbol (a closure or inner function is part of it);
   - it is a constructor: a method whose name is the last segment of its namespace (a private one exists to forbid instantiation);
   - a reference outside its own body lists it in its `target`, or is `unresolved` with its name. A reference inside its body is recursion and does not count.
   Anything left is `dead.symbol` (`warn`, action `review`) with confidence **0.6**, or **0.3** when the language's `dynamic` has a `names` site, or a `members` site and the symbol is a method. Evidence gains `reach` (`module` for the module pass, `references` for this one) and `dynamic` (the sites that lowered it, as `file:line`, at most ten; empty otherwise). Reachability is not followed from roots: a function only a dead function calls is reported once that one is gone.
5. **Per language**, what the producer records and so the confidence of a symbol-pass finding:
   - **Rust**: no dynamic site (no reflection; macros' identifiers are members, strings in attributes are text). 0.6. Inert: `allow`, `warn`, `deny`, `expect`, `inline`, `cold`, `must_use`, `doc`, `deprecated`, `track_caller`, `cfg`, `cfg_attr`.
   - **Go**: no dynamic site: `reflect` reaches only exported names, which are roots. 0.6. Invisible: `//go:linkname` and cgo `//export` comments.
   - **Python**: `getattr`, `hasattr`, `setattr`, and `delattr` calls whose name is not a string literal (a literal is a `text` reference), and `globals`, `locals`, `vars`, `eval`, `exec`, `__import__`, and `import_module` calls, are `names` sites, so in a Python tree that uses one every symbol-pass finding is 0.3. Decorators are attributes; inert: `staticmethod`, `classmethod`, `property`, `abstractmethod`, `override`.
   - **JavaScript, TypeScript**: a subscript whose index is not a literal is a `members` site; `eval` and `Function` calls are `names` sites. Decorators are attributes. Implicit: `constructor`.
   - **Java**: `getMethod`, `getDeclaredMethod`, `getMethods`, `getDeclaredMethods`, and `forName` calls are `members` sites; every Java symbol is a method, so one such call lowers every Java finding to 0.3. Annotations are attributes; inert: `Override`, `Deprecated`, `SuppressWarnings`, `SafeVarargs`.
   - **Clojure**: `resolve`, `ns-resolve`, `requiring-resolve`, `find-var`, `intern`, `eval`, `ns-publics`, and `ns-interns` calls are `names` sites. A qualified symbol (`str/join`) is a member.

## Consequences

- A private function nobody names, in a module something imports, is reported (the Rust fixture's `scale` and `audit_limit`). A function passed as a value, kept in a table, named in a string, or decorated is not.
- Matching unresolved names across the language over-approximates: a method `len` anywhere keeps every `len` live, and so does a local variable or a string `"len"`. Findings are missed, never invented, by these rules; a false positive needs a reference no syntax shows: code generated at build time, a file in another language, a framework that finds functions by naming convention without an attribute, or loading by a computed name, which lowers confidence where the producer sees it.
- The symbol pass holds under `--changed`, since references come from the whole repository; the module pass still reads only the scope's import edges (ADR-058's narrowed-scope caveat).
- Dead clusters (two private functions calling only each other) stay unreported, as in ADR-058.
- The evidence of `dead.symbol` and `dead.export` gains `reach` and `dynamic`, so every existing finding gains two fields; nothing else in them changes.
