# CUPEL_DECISION_152: `tests.coverage` and the files no test loads

**Date:** 2026-10-28 · **Status:** accepted · **Phase:** P10.4

## Context

The v0.2.0 verification (P9 Notes "P9 — v0.2.0") ran `cupel check` on a Python repository whose changed file, `src/shop/shipping.py`, no test imports. `tests.coverage` passed it with `score 0 line_ratio (n 0) · metrics line 0, lines 0, uncovered 0`, while `tests.mutation` reported the same file's 25 mutants uncovered. The cause is in two places. coverage.py reports a file only when it was loaded, unless it is given a *source* (a directory or package): with a source it walks it and reports every file under it, loaded or not, as 0 %. `cupel init` writes the toolchain table's command, `<m> pytest --cov --cov-report=lcov:{out}`, whose bare `--cov` names no source, so the LCOV report has no row for a file no test imported. And `tests.coverage` (ADR-079) reads a symbol whose file has no row as having no instrumented lines, which it does not score: the rule that keeps a declaration-only symbol, or a file of constants, from counting as uncovered also hides a module nobody loads.

Two questions, then. What should `init` write so that coverage.py lists every file of the project? And what should the check make of a map that lists only loaded files, which every `cupel.toml` written by v0.2.0, every custom command without a source, and every committed cache of such a run produces?

## Options

**The source `init` passes.** (a) `--cov=.` always: coverage.py walks a source directory into subdirectories that have an `__init__.py`, and the `src/` of a src layout has none, so `src/shop/shipping.py` is still not listed. (b) `--cov=<package>` for each package found under the root or under `src/`: several `--cov` words, a package scan per root, and a root of loose modules gets none. (c) `--cov=src` when the root has a `src/` directory, else `--cov=.`: one source per root, the two layouts the language's `[namespace] source_roots` already tells apart, and the directory itself is exempt from the `__init__.py` rule, so every module and package under it is listed.

**Where the source is decided.** In the toolchain table alone (it knows no root), in `init` alone (then the joint producer and the coverage producer, which run the command, cannot share it), or in the Python `ProjectInfo` producer's `packages`, the field the table's `<packages>` placeholder is filled from ("the package patterns its commands cover", ADR-037; Go fills it with `./...`). The last gives `init`, `describe`, and the producers one value from one place.

**The joint producer (ADR-084 §3).** It fuses the table's command compared word by word, so `init`'s new command would be `unconfigured` for it and a Python repository would lose the one-run suite. Accepting `--cov[=<source>]` words and running with the configured sources (or, for the bare `--cov` that v0.2.0 wrote, the root's `packages`) keeps the joint and gives the old configuration the new listing.

**What the check does with an unlisted file.** (a) A rule in the check alone: a symbol in scope whose file the map does not list is uncovered when the map lists other files. It would change every language's numbers: `cargo llvm-cov`'s LCOV lists every instrumented file, so a Rust file with no row is one no test binary compiled (a `build.rs`, an example, a module behind a `cfg`), not an untested one; Go's profile leaves out packages without test files; JaCoCo lists every class under the class directories; the Istanbul reports of vitest and jest list loaded files only unless configured otherwise. (b) A property of the map set by the producer that made it: whether the report lists every file that has executable code, or only the files the suite loaded. The check then applies the rule only to maps of the second kind, and a producer that learns its tool lists loaded files only (Go's untested packages, vitest's and jest's defaults) switches the rule on for its language with one line and a fixture, without touching the check.

**The finding.** Reusing `coverage.uncovered-symbol` says "none of its N instrumented lines ran", which is false (nothing was instrumented) and gives the wrong remedy (the first test to write is one that imports the module). A kind of its own, `coverage.unloaded-file`, reported per symbol as the check's other findings are, says what happened and counts the symbol's lines as uncovered.

**N, the lines.** Without a row there is no list of executable lines; the symbol's span stands in: its body's lines, or the declaration line alone for a one-line symbol, the lines `symbol_lines` would read of a listed file.

## Decision

1. **The Python root's `packages` is its coverage source**: `["src"]` when the root directory holds a `src/` directory, else `["."]` (`crates/cupel-lang/src/langs/python/project.rs`).
2. **The table's pytest-cov command is `<m> pytest --cov=<packages> --cov-report=lcov:{out}`**, so `cupel init` writes `pytest --cov=src …` or `pytest --cov=. …` per root, and `describe` shows the template.
3. **The joint `tool.pytest-cov-contexts` fuses `[<launcher>] pytest --cov[=<source>]… --cov-report=lcov:{out}`**: any launcher ending in `-m` or none, one or more `--cov` words, nothing else. It runs with the configured sources; when every `--cov` word is bare, with the root's `packages`.
4. **`CoverageMap` gains `listing`**, `Listing::All` (every file with executable code is listed, a file absent from the map has none) or `Listing::Loaded` (only the files the suite loaded are listed, a file absent from the map never ran); `All` is the default, what a map without the field (a committed suite cache) reads as, and left out when written, so every map of a tool that lists every file is byte-identical to before. `tool.pytest-cov` and the joint set `Loaded` when the command run has no `--cov=<source>` word; `tool.coverage-py` (the same coverage.py under `unittest`) when it has no `--source` word. Every other producer leaves `All`. The rule applies, today, to Python alone.
5. **`tests.coverage`**: when the map's listing is `Loaded` and it lists at least one file, a symbol in scope (test files excluded, as before) whose file the map does not list is reported as `coverage.unloaded-file` (`warn`, so the check fails; action `write_test`; evidence `{lines: N, covered: 0}`, N the symbol's span lines as above), and its N lines count in `lines`, `uncovered`, `uncovered_lines`, and `line_coverage` as uncovered lines do. With listing `All` the check is unchanged: an unlisted file has no instrumented lines and is not scored.
6. **Fixture and goldens.** `crates/cupel-fixtures/repos/unloaded-file/python/`: the P9 shape, a `src/shop` package whose `pricing` module the tests import and whose `shipping` module nothing imports, configured with v0.2.0's bare `--cov` and a committed cache of that run (ADR-079), with its golden `golden/unloaded-file/python.json` showing `coverage.unloaded-file` for each function of `shipping.py` and the check's `lines` counting them with none covered. A second test runs the same fixture with `--cov=src` and real pytest-cov: coverage.py then lists `shipping.py` at 0 % and the same functions are `coverage.uncovered-symbol`.

## Consequences

- A changed Python file no test imports fails `tests.coverage` as it fails `tests.mutation`, through either half: a repository configured by this release's `init` (or a v0.2.0 configuration run through the joint) lists the file at 0 % and reports `coverage.uncovered-symbol`; a configuration run as written without a source reports `coverage.unloaded-file`.
- The `coverage-map` schema gains an optional property (`x-cupel-optional`, as `notes` is; `required` and the version unchanged); the Python `project-info` fact, the Python `init` goldens, the `describe` goldens of the Python toolchain, and the `tests.coverage` describe golden change where the command or the new kind appears, and nowhere else.
- The joint always runs with a source (the configured ones, else the root's `packages`, which detection always fills), so the map it makes lists every file; its per-root `listing` is set from the words it ran, and the merged map of several roots reads as `All`, which is what every such run is.
- `static.crap` and the per-symbol coverage others read (`symbol_coverage`) still treat an unlisted file as unmeasured; giving them the same rule is a follow-up once `tests.coverage`'s is seen on real repositories.
- Reopened by a fixture, per language: Go (a package without test files is absent from the profile), JavaScript and TypeScript (vitest's and jest's reports list loaded files only in their default configurations). Each is one `Listing::Loaded` in its producer, a fixture with an unloaded file, and that language's goldens; the check needs no change. Rust (every instrumented file listed), Java (every class), and Clojure (every instrumented namespace) are not affected.
- The root's source is one directory; a Python root whose packages live beside `src/` as well, or whose members (nested `pyproject.toml`) hold their own `src/`, gets `src` alone and may edit `cupel.toml` to add `--cov` words, which the joint accepts.
