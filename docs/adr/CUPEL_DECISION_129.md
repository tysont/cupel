# CUPEL_DECISION_129: Cupel's own gate at `--depth deep`: changed on every push, tree on `main`, a local budget, and the deep rules

**Date:** 2026-10-20 · **Status:** accepted · **Phase:** P9.0

## Context

Until P9 Cupel graded itself at the default depth, `standard`, with `tests.mutation` and `tests.flaky` skipped (P2.10, P3.4, P3.5 Notes): `make dogfood` ran static checks over the tree and nothing that executes the suite more than once. The owner's P9 ruling puts Cupel's own gate at `--depth deep` in CI first (track (b)), so that the follow-up burn-down and the external dogfood keep a deep gate green. The plan's P9.0 bullet asks for a measurement of a deep run on the tree and on a one-function change, the scope and frequency those measurements justify, the deep checks' rules in `[gate.changed]` and `[gate.tree]` at the strictest values the tree sustains (`tests.mutation.score` at least 0.80), fixes for what the deep run finds, and the deep `survey` rankings as a baseline. After the 2026-10-19 crash the owner ruled on the scoping (recovery ruling (3)): deep on `--changed` for branch and pull-request CI, deep on the tree only on a push to `main`, and the local dogfood under `--budget`. The P9 preamble also leaves to this step whether the repository needs a second copy of the agent guide.

The questions:

1. Which deep checks the dogfood runs, on which scope, and when.
2. How a local run is bounded while CI runs the full set.
3. What the gate rules on the deep checks are.
4. How the matrix test stops making every mutant run every (check, language) pair.
5. Whether the repository holds an agent guide beside the README's generated one.

### Measurements

Taken on 2026-10-20 on the owner's 8-core Apple Silicon Mac with `make dev-setup`'s tools, through `scripts/dogfood.sh` (one dogfood at a time on the machine), with `--format json` for the per-check durations and the fact store's `durations` table for the producers. The machine was not idle: three other agents were building and running Cupel's suite, and the load average was 40 to 75 during the tree run and 16 to 132 during the one-function run. The numbers are upper bounds for an idle machine, not estimates of one.

**Tree** (`check --depth deep --gate --no-install --skip tests.flaky --skip conc.race --skip tests.mutation`, 567 files, 6 953 symbols): 2 170 s wall, exit 0, `[gate.tree]` passed. Producers: the instrumented suite run that makes the coverage map (`tool.llvm-cov-nextest`) 1 219 s; the property engine (`engine.property`, which reruns the suite's property tests at the deep case budget) 889 s; clippy (`tool.analyzers`, Rust) 36 s; mypy and ruff 1.3 s; the five language producers 15 s together. Checks over those facts: `static.crap` 2.3 s, `static.clones` 2.2 s, `tests.coverage` 1.6 s, every other check under 1 s. What the run reported: `tests.coverage` line 0.968 of 41 674 lines with 45 uncovered symbols (`warn`); `static.crap` max 20, mean 2.14, 431 `crap.watch` (`info`); `gen.property` 20 properties, none falsified, 305 functions without one (`info`); `gen.fuzz` no target (`fuzz.target-missing`, cargo-fuzz); `perf.bench` no benchmark and no base on a tree run; `spec.contracts` no project root declares a contract library; `static.analyze` 112 findings, all in the three Python scripts Cupel ships (76 in the PIT plugin, 33 in the metamorphic harness, 3 in the Hypothesis plugin template), 104 of them mypy errors; `tests.assertion-density` 175 sparse tests and 31 sparse files (`warn`).

**One-function change** (the same flags without `--skip tests.mutation`, under `--base HEAD` with one function, `metrics::symbol_coverage`, edited in the working tree; the scope was its file, 12 symbols): 2 307 s wall, exit 0, `[gate.changed]` passed. Producers: the mutation engine 1 395 s for 12 mutants (all schemata, all killed, score 1.0); the per-test coverage run the mutation engine and `tests.coverage` need 875 s; clippy 12 s; criterion 1.3 s. `tests.coverage` 1.0 over the scope's 80 lines, `static.crap` max 3.

Two findings follow. A deep run's cost is the suite, not the checks: on the tree the two suite runs are 97% of the wall time; on one function the mutants and the per-test map are 98%. And mutation is per mutant: 12 mutants of one function took 23 minutes at this load, so the tree's thousands of mutants are out of reach of any per-push job.

## Options

**Scope and frequency.** (a) Deep on the tree on every push: each push pays the tree's suite runs (36 minutes here) and, with mutation, thousands of mutants; rejected. (b) Deep on `--changed` on every push and pull request, deep on the tree on a schedule under `--budget`: a scheduled job reports after the fact, to nobody in particular, and a budgeted tree run is `partial` by design. (c) Deep on `--changed` on every branch push and pull request, deep on the tree (without mutation) on each push to `main`, where there is no merge base to diff against: every change is graded deep before it merges, and `main` is re-graded whole after it does. The owner's ruling is (c), and the measurements fit it: the tree run without mutation and a change's mutation run are each well inside the dogfood job's 90-minute limit even at the measured load.

**Which deep checks are skipped.** `tests.flaky`: its engine reruns the whole suite three times one test at a time, and with cargo-nextest as the runner (Cupel's, ADR-083) it does not rerun at all and the check ends in `error`, which would fail the gate on a check that cannot run. `conc.race`: Miri interprets every test and cannot run the process spawning and file access almost all of Cupel's tests do (ADR-105 Consequences). `tests.mutation` on the tree only: the measurement above. Everything else `deep` selects runs.

**Bounding a local run.** (a) A lower depth locally: a developer's dogfood would then not run what CI runs, and a red CI run would be the first sign of a deep finding. (b) `--timeout`: stops whatever is running at the deadline, so the most valuable check may be the one cut. (c) `--budget`: the depth's checks are chosen by value per millisecond from this repository's recorded costs, what does not fit is `skipped` with `reason: budget` and its estimate, the run is `partial` (exit 5), and `next_actions` gives the command that runs each skipped check alone. (c) is what the owner's ruling names. The value: 30 minutes. The measured one-function change took 38 minutes at a load average up to 132, which a budget of 30 minutes cuts (mutation and the per-test coverage run do not both fit, so the developer sees `tests.mutation` skipped with its estimate); on a quieter machine the same change fits. A budget of 20 minutes would leave out mutation of any change even on an idle machine once its recorded cost passes 20 minutes, which removes the check P9.0 exists to run; an hour would not bound anything a developer waits for. CI clears the budget with `DOGFOOD_BUDGET=` and runs the full set.

**Gate rule values.** The design's example values (`static.crap.max < 30`, `perf.bench.regression < 5%`) or the tree's own measured values. The plan asks for the strictest values the tree sustains, so the measured ones, rounded down where the metric moves with test timing.

**The matrix test under mutation.** The matrix test was one `#[test]` that ran every (check, language) pair, so the per-test coverage map attributed to it every line any pair executed, and every mutant in any check, producer, or language module reran all of it. Options: (a) leave it and accept that each such mutant costs the whole matrix; (b) one generated `#[test]` per pair from a build script, which would have to compute the registries at build time; (c) a custom harness (`harness = false`) through `libtest-mimic` that names one trial per pair from the registries at run time, two per pair (its golden or skip, and its declared-facts run), so nextest runs each pair in its own process and the per-test map attributes to each pair only the code its run executes. (c) costs one dev-dependency and keeps the registries the only list of pairs; listing the trials computes no support, so `nextest list` stays fast.

**The agent guide.** (a) A committed `AGENTS.md` or `CLAUDE.md` beside the README: plan §2.6 allows no Markdown outside `README.md` and `docs/`, and a second copy of the guide drifts from the binary that generates it. (b) The README's "For agents" section alone, generated by `make readme` from `cupel describe --agent` and checked by `crates/cupel-cli/tests/readme.rs`: one copy, which cannot go stale. Agents working on Cupel itself already have their rules in `docs/plan/p9/common.md` and the plan.

## Decision

1. **`make dogfood`** runs `scripts/dogfood.sh $(CARGO) run --quiet --package cupel-cli -- check --changed --depth deep --budget $(DOGFOOD_BUDGET) --gate --no-install --skip tests.flaky --skip conc.race --format text`; `DOGFOOD_SCOPE=tree` drops `--changed` and adds `--skip tests.mutation`. `DOGFOOD_BUDGET` defaults to `30m`; empty, the recipe has no `--budget`.
2. **CI's `dogfood` job** runs `make dogfood DOGFOOD_BUDGET=` on every branch push and pull request and `make dogfood DOGFOOD_SCOPE=tree DOGFOOD_BUDGET=` on a push to `main`. It installs every tool the `check` job installs, through the composite action `.github/actions/tools` both jobs use (the deep run executes the suite under coverage as its baseline, and that suite drives every tool; the first run on GitHub with only cargo-nextest and cargo-llvm-cov failed 26 baseline tests), removes the runner's preinstalled SDKs to free the disk the mutation slots' workspace copies need, builds with `CARGO_PROFILE_DEV_DEBUG=0`, and has a 90-minute limit. `crates/cupel-cli/tests/dogfood.rs` pins both recipes, the empty-budget forms, and the job's steps.
3. **Gate rules** added to both `[gate.changed]` and `[gate.tree]`: `static.analyze` `none`, `static.crap.max <= 20` (the tree's maximum), `gen.property.falsified == 0`, `spec.contracts` `none`; to `[gate.tree]`, `tests.coverage.line >= 0.96` (the tree measures 0.968); to `[gate.changed]`, `tests.coverage` `none` (no changed function without coverage) and `tests.mutation.score >= 0.80`. The changed gate's coverage rule is `none` rather than the line ratio because `tests.coverage` scores a scope with no instrumented line 0 (a deliberate convention its tests pin), so a change that touches only Python scripts, tests, or configuration would fail a ratio floor; `none` is the stricter rule wherever there is a line to cover. `gen.fuzz` has no rule: Cupel has no fuzz target, and CI's dogfood job has no cargo-fuzz, so the check would be skipped there and a rule on it would fail the gate on every push. `perf.bench` has no rule: Cupel has no benchmark, so `regression` is always 0.
4. **What the deep run found and was fixed**: the 112 `static.analyze` findings. The PIT plugin, the metamorphic harness, and the Hypothesis plugin are annotated to pass `mypy --strict`; the plugin template's case budget is `CASES = int("{cases}")`, so the file is valid Python before Cupel writes the number in; the PIT plugin's ruff findings are fixed (`from xml.etree import ElementTree`, a parenthesized concatenation, `check=False`); the harness's four `except Exception` clauses, which catch whatever the project's own code raises, carry `# noqa: BLE001` with that reason. What was not fixed is listed under Consequences.
5. **Combining an empty scope.** The branch's own dogfood found that `tests.mutation` scored a change with no mutant 0 although each language scores it 1 ("1 when nothing was scored"): `metrics::weighted_mean` and `outcome::weighted`, which combine languages' ratios weighted by their targets, returned 0 when no language had a target, and every result passes through them, even a single language's. Both now return the languages' own values averaged when nothing weighs, so each check's convention for an empty scope survives the combining; a check whose languages score an empty scope 0 (coverage, `tests.quality`'s ratios) still combines to 0.
6. **The matrix test** is a `libtest-mimic` harness with one golden-or-skip trial and one declared-facts trial per pair (`crates/cupel-fixtures/tests/matrix.rs`, `Registries::pair_ids`, `verify_pair`).
7. **No second agent guide.** The README's generated "For agents" section is the one copy.

## Consequences

- Every change merges only after Cupel's deep checks pass on what it changed, mutation included, and `main` is re-graded deep after each merge; a deep finding reaches a developer locally before CI when the budget allows, and otherwise as a `skipped` entry naming the command that runs it.
- A local `make dogfood` can exit 5 (`partial`) while CI's run of the same change exits 0; the skipped checks are listed and CI runs them. `make dogfood DOGFOOD_BUDGET=` runs the full set locally.
- CI's deep runs are unmeasured on GitHub's runners (4 vCPUs, two mutation slots); the 90-minute limit rests on the local measurements above. A change that touches many functions mutates every function of every changed file and may need longer; the job's limit is the place to raise.
- Not fixed, recorded as open items: the 45 uncovered symbols (`tests.coverage` `warn`; several are reachable only through a terminal prompt or a tool CI does not install, such as atheris), which the tree's `tests.coverage.line` rule holds from growing and the changed gate's `none` rule fails on whenever a change touches one; the 175 sparse tests and 31 sparse files of `tests.assertion-density`, which no gate rule covers yet; no fuzz target (`fuzz.target-missing`); no benchmark for `perf.bench` to compare; no contract library for `spec.contracts` to read.
- The tree run has no reference for relative rules (P9.1): a fresh CI checkout has no fact store. Caching `.cupel/` between runs would give it one; until then the tree's ratchets stay literals.
