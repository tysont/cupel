# CUPEL_DECISION_082: Rust mutant schemata

**Date:** 2026-10-15 · **Status:** accepted · **Phase:** P4.1

## Context

Under the file-copy engine (ADR-080) every Rust mutant is its own build: the mutated file is written into a slot, cargo rebuilds its crate and every dependent, and the suite runs. On Cupel that is several minutes per mutant (plan P3 Notes, "P3.4 — timing", "P3.6 — measurement"). Design §9.3 item 4 replaces the per-mutant build with mutant schemata: rewrite each site as `if cupel_mutant_id() == N { mutated } else { original }`, build once, and select the mutant at run time with `CUPEL_MUTANT=N`; validate the schemata build before any mutant runs and fall back to file copies when it does not compile. The design leaves open: where the language-specific rewrite lives given the crate graph; what a site's gated expression is when a site is an operator token; how operands keep their single evaluation, short-circuiting, and borrows; which positions cannot hold an `if` at all; how the id is read and where the reader goes; how fine the fallback is; what timeout a schemata mutant gets; and how the fact says which strategy produced an outcome.

## Options

**Where the rewrite lives.** (a) In `cupel-lang`'s Rust module behind a trait in `cupel-core` that the registry hands the engine, as design §8.4 sketches: a new registry surface in `cupel-core` and a new path through `ProduceCtx`, for one implementation. (b) `cupel-mutate` depends on `cupel-lang`: a new edge in the crate graph (plan §2.1) for one parser call. (c) `cupel-mutate` parses with `tree-sitter` and `tree-sitter-rust` itself (both already workspace dependencies): no change to the graph of Cupel crates; the engine names one language, in one module.

**The gated expression.** A site is a token (`>=`), a literal, or an expression. (a) Bind the operands once (`{ let (l, r) = (a, b); if … { l > r } else { l >= r } }`): breaks short-circuiting for `&&`/`||`, moves operands a comparison only borrows, and loses the expected type that flows into a literal. (b) Gate the smallest whole expression holding the site — the binary or compound-assignment expression of an operator token, else the site's own node — and give every branch that expression's full text: each branch is exactly the original or exactly one mutant, so evaluation order, short-circuiting, borrows, moves, and type inference are those of the code a file copy would build. Nested sites duplicate text; since only mutant `N` is live in the branch for `N`, every other site in that branch can stay original, so the growth is linear in the sites an expression holds, not exponential.

**Fallback granularity.** (a) Per file: one site that does not type-check under schemata sends the whole file to file copies. (b) Per site, by bisection: many builds. (c) Per file, with the compiler's help: when the validation build fails, the sites on the lines its errors name leave the schemata and the file is rebuilt, a bounded number of times, before the whole file falls back.

**Timeouts.** (a) Time a second reference run after the schemata build, so a schemata mutant's limit excludes the build: one more run of the selected tests per slot per file. (b) Use the validation run, build included, as the reference: the same limit a file-copy mutant gets (ADR-080 §9), no extra run.

## Decision

1. **Strategy per language.** `cupel_mutate::schemata::rewriter(lang)` is the engine's question: `Some` (a `Rewriter`) for `rust`, `None` (file copies) for every other language. `[lang.<id>] mutation = { strategy = "schemata" | "file-copy" }`, default `schemata`; `schemata` means "where the language has a rewriter". The Rust rewriter lives in `cupel-mutate/src/schemata/rust.rs` and parses with `tree-sitter-rust` (option c); the crate graph of Cupel crates is unchanged.
2. **Rewrite.** Each mutant of a file is a gate with id `N` = its 1-based position among the file's mutants in the run. A gate's target is the binary or compound-assignment expression of an operator token, else the site's node (a literal, a condition, a returned value, an expression statement). Gates sharing a target share one chain: `if cupel_mutant_id() == N1 { V1 } else if cupel_mutant_id() == N2 { V2 } else { R }`, where `Vk` is the target's original text with mutant `k` applied and `R` the target with its inner gates rendered the same way. The chain is parenthesized where its parent needs it (an operand, a receiver, a cast, an index, a statement, the left of an assignment, a let chain, the value of a `let … else`) and nowhere else (rustc's `unused_parens` warns on the rest). Lines are preserved: a multi-line variant is folded onto one line, and a target whose variant cannot be folded safely (it holds a line comment or a literal spanning lines) is excluded.
3. **Reader.** One private function appended at the end of the mutated file, so no line moves: `fn cupel_mutant_id() -> u32`, reading `CUPEL_MUTANT` once into a `OnceLock` (0 when unset or not a number). A gate inside `k` inline `mod` blocks calls it as `super::…::cupel_mutant_id()`. Every engine run sets `CUPEL_MUTANT` explicitly — the mutant's id, or `0` for reference runs and file copies — so a variable inherited from an outer run (Cupel's own suite under mutation) never selects a mutant in a fixture.
4. **Excluded sites** (recorded per mutant in `fallback`, run as file copies): inside a pattern (match arms, `let`/`if let`/`for`/parameter patterns, closure parameters); in a constant context (`const` and `static` items, `const` blocks, `const fn` bodies, array lengths and array types, enum discriminants, const generic arguments and parameters); inside a macro's token tree or a macro definition; inside an attribute; a tuple field index (`t.0`); a constant the compiler evaluates (a literal that is an index, the divisor or shift of `/`, `%`, `<<`, `>>`, or whose sibling operand is a literal, and an operator between two literals), because deny-by-default lints (`unconditional_panic`, `arithmetic_overflow`) reject such a mutant as a file copy but cannot see it behind a run-time switch, which would turn `unviable` into `killed`; a site whose node is not found where its span says.
5. **Validation and fallback** (option c). Before any mutant of a file runs, every slot the file uses writes the schemata source and runs the file's selected tests with `CUPEL_MUTANT=0`; all must be green. When the build fails, the gates on the lines the compiler's `error` diagnostics name in that file leave the schemata (`fallback`: "did not compile under schemata"), and the file is rebuilt, at most twice more; if it still fails, or the errors name no gated line, or the tests fail, the whole file runs as file copies with the reason in every mutant's `fallback`. A failed validation is never an error of the production.
6. **Running.** Gated mutants of a file run first, each with `CUPEL_MUTANT=N` and no write, so no rebuild; excluded ones then run as file copies in the same slots. A slot's timeout is `max(2 s, timeout_factor × its validation run)` (option b): the same limit a file copy gets, with no extra run.
7. **Payload.** `MutationOutcomes` version 2: each `Mutant` gains `strategy` (`schemata` | `file-copy`, `null` when it was not run here) and `fallback` (why a mutant of a language with a rewriter ran as a file copy; `null` otherwise), both defaulting to `null` so rows stored by version 1 still read. `tests.mutation` reports the metrics `schemata` and `fallback` (mutants run this time each way) and one note per fallback reason.
8. **Reuse.** The strategy is not part of the cache key (ADR-080 §10): a mutant's outcome does not depend on how it was built, and the parity test proves it on the fixtures. A reused mutant carries the stored `strategy` and `fallback`.

## Consequences

- A Rust file's mutants cost one build per slot instead of one per mutant; each mutant then costs only its test run.
- Known differences from file copies, accepted: a mutant that only loops slowly may time out under one strategy and not the other (limits are the same, builds are not); `line!()`, `column!()`, and panic locations inside a folded variant report the target's first line; a mutant that changes what a `const` or pattern means is never gated.
- Go schemata are decided separately (ADR-005). A rewriter for another language is one module returning gates; the engine does not change.
- The fallback costs builds: up to three failed validation builds per file before file copies, each the build the file copy would have needed anyway.
