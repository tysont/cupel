Set by hand: `runner = "cargo-nextest"` (ADR-138 §2: per-test selection, durations, and ADR-147's exclusion for Rust mutants) and `mutation = { jobs = 1 }`. The brief asked for `jobs = 2`; the first survey ran with it, and `tests.mutation` ended in `error`: `test_deserialize_from_stream` binds the fixed port `localhost:20000`, so the reference runs of two slots collide, and an unmutated file whose reference is red fails the whole production. That survey also left two of the test's processes running for an hour after it ended (holding the heavy lock), which is the Cupel defect fixed below; with one slot nothing collides.

The ten targets of the whole-tree survey are all test functions (below), so the deep check on their files (`tests/lexical/num.rs`, `tests/regression/issue795.rs`, `issue845.rs`, `issue953.rs`, `issue979.rs`, `tests/test.rs`) mutates nothing: `tests.mutation` has no site in a test file. That is ADR-138's open item (protect-first ranks test functions, whose protection nothing measures, before every measured one), so the method was run as written and then once more over production code: the same survey scoped to `src`, whose ten targets name `src/error.rs`, `src/ser.rs`, `src/number.rs`, `src/value/de.rs`, `src/lexical/math.rs`, `src/value/index.rs`, and `src/map.rs`, and the deep check on those files. Both deep checks reuse the survey's stored mutant outcomes (`reused 140`, `executed 0`), so their mutants are the survey's. Raw envelopes (0.1–1.0 MB) stay in the agent's scratchpad.

The first survey left two `test_deserialize_from_stream` processes (port collision, then a hang) alive an hour later, holding the heavy lock's descriptor and blocking every agent; a test that allocated would have been outside every budget. A run is now its group and every descendant, whatever group; a kill stops, relists, and kills every group (ADR-148 §3 amended). Commit e235f85.
